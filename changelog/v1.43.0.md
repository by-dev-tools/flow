## v1.43.0 — 2026-09-13

- **The PR now says which version of flow actually ran the pipeline (FB-0107).** A `/flow:*` skill
  invoked from a repo does **not** run that repo's working tree — Claude Code resolves the skill from
  the *installed* marketplace plugin. Measured in flow's own workspace: the install was **1.29.0**
  against a `main` at **1.41.0**, a twelve-release gap no gate noticed, found by accident during a
  pre-archive check. `/flow:ship` and `/flow:ship-spike` now render **four labelled rows** in the
  `## Flow run` table from `skills/ship/lib/plugin-provenance.py`: installed version, marketplace
  HEAD, where fenced-block helper libs resolved from, and where `!`-preprocessor scripts resolved
  from. Plus a callout naming any skill or agent the branch declares that was **not invocable at all**
  in the run.
- **Four rows and not one number, because one run draws from two versions.** The measured rule:
  *everything Claude Code resolves comes from the installed tree; everything the Bash tool resolves
  comes from the working tree.* `CLAUDE_PLUGIN_ROOT` is unset in Bash-tool calls and set in
  `!`-preprocessor blocks, so the same `${CLAUDE_PLUGIN_ROOT}/…` string names different files
  depending on who expands it. A single "plugin version" line would be **wrong**, not merely
  ambiguous — it would report the installed version while the fresh engines were in fact executing.
- **Reports; never gates.** Drift does not route to the draft manifest and does not block a ship. A
  *stable* reviewer is partly a feature: a ship pipeline with a bug that skips a reviewer should not
  be the thing running its own ship, and a branch that breaks ship could not ship itself. Two
  predicates are exposed and deliberately **not** collapsed — `report_drift` (installed vs branch) for
  the PR body, `update_available` (installed vs marketplace HEAD) for an updater. A feature branch
  declares an unreleased version by construction, so keying an updater on the branch comparison would
  make it fire forever, including after a fully successful update.
- **Dev-side (not shipped):** a `SessionStart` hook keeps flow's own dev workspaces current, ported
  from health-tracker#116 — flow built that auto-updater for consumers and never pointed it at itself.
  An update failure is **loud**, never swallowed: a silent-on-failure auto-updater is strictly worse
  than none, because it manufactures confidence about the version, which is this release's own bug one
  level up. It converges the *next* session and cannot fix the current one (`plugin update` requires a
  restart), which is why the report is the load-bearing half.
- **New eval harness** `run_plugin_provenance_evals.py` (227 checks, CI-wired). Every row is asserted
  in **both** polarities, since a drift warning alone is satisfiable by deleting the row.

- **SAFETY — two issues found by `/flow:security-review` before ship.** A version string from the
  repository under review could inject markdown into the PR body and **forge a "✓ matches this branch"
  verdict** while hiding the real warnings in an HTML comment (reproduced, then fixed by sanitising at
  read time). And flow's own dev-side SessionStart hook executed repo-tracked, branch-rewritable code,
  so checking out an external PR and starting a session was arbitrary code execution for a *maintainer*
  — consumers were never exposed, since `.claude/` is not part of the published plugin. The hook now
  resolves its engine only from the installed tree and refuses to fall back to the checkout.

- **A hook hardening was attempted and abandoned on a measurement, which is recorded rather than
  quietly dropped.** Hash-checking the session-start hook script would have closed the remaining
  maintainer-side residual *if* Claude Code re-prompts when a `settings.json` hook command string
  changes. Measured: a first-ever hook string ran with no prompt, a changed string ran with no
  re-approval, and no hook-approval state is stored at all — so the check would have enforced nothing.
  Documented in the new `CONTRIBUTING.md` instead, together with the experiment that would make the
  fix viable on an interactive machine.

**Breaking changes:** none. The four rows are additive to the `## Flow run` table; a missing reporter
warns and continues rather than failing a ship.
