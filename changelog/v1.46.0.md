## v1.46.0 — the prototype is the gate (D1 Phase 2)

**For UI work, the first thing you approve is now a prototype, not a plan.** `/flow:prototype` writes a short design brief, reviews it before anything is built, produces an HTML prototype, checks it through two design lenses, and hands you the page with click-to-pin comments. You approve a look you can see.

**This replaces the plan gate for that path — it does not add a gate.** Exactly one human gate before execution, always: prototype approval or plan approval, never both and never neither. The technical plan is written afterward, against the design you signed off, and is machine-reviewed.

- **Feasibility is asserted, not advisory.** On a non-web target the prototype must carry a feasibility read naming what is standard, custom, expensive or infeasible to build natively — and the gate *refuses to record an approval* without it, so you never approve a look that can't be built.
- **Proportionality is declared, not guessed.** A brief saying `Mode: tiny` skips the prototype entirely and routes back to the plan gate. No tuned size threshold to drift.
- **A plan always exists before code.** Mechanically asserted from committed state, so it survives a lost workspace.
- `/flow:doctor` now reports whether the prototype-first path is actually live, not just whether `role` is set.

Phase 3 (auto-writing the technical plan and machine-gating it) is not built yet.
