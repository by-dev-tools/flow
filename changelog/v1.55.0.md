## v1.55.0 — `/flow:audit-coverage` can read behaviour-bearing prose

> **Written after the fact, in the v1.56.0 PR (2026-10-02).** #172 shipped v1.55.0 **without a changelog entry** and nothing caught it, so this entry was reconstructed from that PR's own record — `dev-docs/history/2026-09-30-audit-coverage-reads-behaviour-bearing-prose.md` — rather than from the work itself. Treat it as a faithful summary, not as a release note written by the people who shipped it: the history entry is the primary source, and anything stated more confidently here than there is this entry's error.

`/flow:audit-coverage` never showed the reviewer a `.md` file. On a repo whose deployed surface *is* prose — prompts, skills, rule files — that made the completeness gate blind to most of what changes.

> **The exclusion everyone pointed at was not the cause.** A `.md` path never matched `sourceFilePatterns` in the first place, so the `|\.md$` clause was belt-and-braces and deleting it would have changed nothing. This is an **inclusion** change, not an exclusion edit.

- **Say it.** With the slot unset, a run prints `[audit-coverage] WEAKENED · DOC-BLIND` naming every changed doc-shaped file it did *not* read, and says which predicate matched them — the consumer's own declaration, or flow's built-in guess, which it prints so you can paste it into the slot.
- **See it.** New **`behaviorBearingDocPatterns`** config slot (schema 36 → 37 slots), **empty by default**, so no consumer's result changes until they opt in. When set, matching paths are unioned back into the behaviour diff *after* the source filter, minus test and fixture paths. A slot that is invalid, and one that compiles but matches nothing, are both flagged — a vacuous pattern reads fewer files while looking healthy.
- **Fit it.** `head -c` over a concatenation made files late in `sort -u` order **entirely invisible** once the 60 KB evidence cap bound. Replaced with max-min fair-share allocation, which **names every file it cut**. On #158's 15-file shape: 13 files at full size, 2 cut, **0 invisible**, total exactly 60,000 bytes.

**Measured.** On #159's reconstruction — a PR whose five known gaps all lived in a `.md` the diff never selected, and which therefore scored 0 of 5 for reasons no prompt change could have moved — the slot brings the file into evidence and the same case scores **2 of 5 and 1 of 5** single-run over byte-identical evidence, finding **disjoint** gaps, **union 3 of 5**.

**Breaking changes:** none. The slot is empty by default and the two other parts only change what a degraded run *says* about itself.

**Known limitation, and v1.56.0 is the fix.** Selecting the prose was only half the job: the reviewer's own instructions still said doc changes are not behaviours, so the evidence arrived and was suppressed. The `DOC-BLIND` guess also only knows `skills/`, `agents/` and `rules/` — if your deployed prose lives anywhere else, nothing will mention it, so do not read silence as coverage.
