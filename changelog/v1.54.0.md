## v1.54.0 — the technical plan writes itself, and a machine gates it

D1 Phase 2 (v1.48.0) moved a UI change's first human gate from the plan to a prototype. This is the other half. After that gate, `/flow:autoplan` writes the technical plan **against the approved prototype** and reviews it by machine — no second human gate, because there is not one to hold.

**That is not less control, and the direction matters.** A prototype is strictly *more* information than a written plan: the human looked at the thing and clicked it, rather than reading a description and imagining it. What replaces plan approval is three arms, and one rule that governs all of them.

> **A GREEN verdict requires every arm to have RUN, evidenced, and returned nothing. Absence of findings is never by itself a pass.**

That is not belt-and-braces. `/flow:audit-coverage` has **perfect precision across every measured run and recall between 60% and 100%** — so a flag is reliable evidence and **silence is evidence of nothing**. A gate keyed on "the reviewer found nothing" would report clean over exactly the half of the surface nobody declared.

- **Arm A — criterion quality. Deterministic.** Vacuity (`extract-criteria.py` + `criterion-specificity.py`) and pinning (`walk-pin-lint.py`), invoked directly. **It reads their output, never their exit status**, and that is load-bearing rather than stylish: both tools exit `0` on *every* verdict, so an exit-code gate is green on all input. The first draft of this feature cited `walk-pin-lint.py … → exit 0` as the evidence the lint worked — on a file carrying 591 unpinned checkboxes. Pinning is scoped to the **active block**, or the arm is red forever in any repo that retains shipped ones.
- **Arm B — completeness. Best-effort, never silent.** `/flow:audit-coverage` in source mode against the prototype's source, run at a declared depth and unioned. **When two passes disagree, the finder wins**: given perfect precision, a gap seen once and missed once is a *recall event*, not counter-evidence, so a 1-of-2 finding carries identical standing to a 2-of-2 one. The pass count is provenance and never touches the verdict. The output always states the depth and what that depth is worth — 1 pass ≈ 82% and 4 = 100% are measured; **2 is between and unmeasured**, and it says so rather than interpolating.
- **Arm C — conformance + experience. Not new.** It is `/flow:review-brief`, pointed at the plan. The skill generalized from brief-only to **any reviewed artifact**: the caller now names the artifact, the next step, and its own identity, so the plan call site cannot return a verdict pointing back into the prototype phase that finished before it ran. It also now reports a reviewer that **DID NOT RETURN** — without that, three dead spawns and three clean spawns are the same zero findings.

**The third gate is untouched, and that was one criterion away from not being true.** `plan-discipline` says a **LOW** confidence verdict is an automatic human gate: *"The plan cannot proceed."* D1 moves **plan approval**; it does not move that. A LOW verdict routes to `[decision-required]` like any other blocking finding.

**An unresolved decision pauses and escalates** — worker → orchestrator → human — and never proceeds silently. Escalation is not a branch that can be flipped off; any decision entry makes the verdict RED by construction.

**Runs on the prototype-first path only.** `collapsed` and `classic` both keep `pre_execution_gate: "plan"`, so the human still gates those plans and there is nothing for a machine gate to replace. An unrecognized path **refuses** rather than defaulting: a depth nobody declared cannot later be told apart from a procedure that did not run.

**New:** `/flow:autoplan` · `skills/autoplan/lib/gate.py` · `evals/run_autoplan_evals.py` (144 checks, CI-wired) · `walk_extract`'s `first_heading_line` / `source_heading_line`, the only field that identifies *which* Spec-walk block was read — `source_heading` is the identical string `**Spec-walk:**` for every unqualified block and `block_count` is a file-wide total, so an assertion on those passes whether or not the property holds.

**Breaking changes:** none to any output contract. `/flow:review-brief` keeps its name (renaming a shipped, model-invocable skill would break consumers for a cosmetic gain) and its no-argument behaviour; what changed is that its verdict's next step is now supplied by the caller, with the D1 Phase 1 shape as the documented default for direct human invocation.

**Known limitation, stated rather than implied.** The escalation shares its wording with `/flow:ship`'s FB-0075 renderer but not its engine — that one is draft-PR-shaped (`residual`, `class`, `kind`) and no PR exists at this gate. One format, two implementations, with an eval asserting the header still matches; unifying them behind a shared entry shape is on the roadmap (D1f).
