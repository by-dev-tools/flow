## v1.61.0 — one opener per worker message, and "where things stand" without scrolling chat

Two orchestrator-seat surfaces, one theme: make the seat's chat readable on a phone. Nothing here changes a gate, a verdict, or any output contract.

> **A convention stated in four places is held together by author memory.** So the eval derives its site list by grepping for the contract, and a fifth site that states the ping contract without the label fails.

- **Worker→seat messages open with `[w:<short-name>] <STATUS>`.** `<STATUS>` is exactly one of `GATE` · `DONE` · `BLOCKED` · `FYI`, under a fixed mapping — completion → `DONE`, blocking question → `BLOCKED`, stall → `BLOCKED`, parked at a plan gate → `GATE`, no action needed → `FYI`. A stall gets no status of its own because the seat's next action is identical to a block's and the body carries the distinction; a fifth token costs scanning value exactly when the human is skimming. The sender comes first so the line survives truncation to one row, and the bracket keeps the opener greppable.
- **Short-names must be unique across live workers,** and `/flow:spawn` now tells the seat to check the name against the backend's `listWorkers` verb *before* writing the brief — and, when that verb is unavailable, to state in the dispatch report that uniqueness was **not** verified, so an unchecked name never reads like a checked one. This was earned the obvious way: a seat sent its status pings under a short-name a live worker already held, so two senders shared one label and the opener identified nobody. (The first attempt at this check pointed at the admission-control sweep, which filters by the *current* item's slug and therefore could never surface another worker's name — it would have returned "no collision" for the very collision that earned the rule. Caught in review before release.)
- **Two state vocabularies, deliberately different sizes.** Worker *messages* carry exactly four statuses, closed. The *digest* carries those four plus two derived values, `WORKING` and `SILENT`, which no worker can send — because a worker killed by the rate limit has no turn in which to ping, so it reports nothing and its backend status reads `idle`, indistinguishable from healthy. That is the state the digest most exists to surface. `/flow:orchestrate` §8 now names both sets, says why a set closed over *what a sender can utter* differs by construction from one closed over *what an observer can conclude*, and carries a do-not-unify rule with **three** clauses — adding a derived value to the message contract, deleting one from the digest, and relabelling a derived row as reported are all regressions. It is pinned as a **set relation** rather than as prose: the `Set` column is parsed, and the message set must equal the four while the digest set must be a strict superset differing by exactly `WORKING` and `SILENT`.
- **`/flow:orchestrate` gains a digest-only path** for "where do things stand". It re-runs the derivation that already exists (steps 2–4: backend worker state, open branches + open PRs, last-activity quiet times), prints one phone-sized table with PR numbers hyperlinked, and **stores nothing** — a status table with a `status` column was measured stale within minutes, reading "dispatched" for three workspaces the API already reported deleted. It **deliberately skips steps 5 and 6**: re-addressing the ping channel mid-program would point every live worker at whichever session ran the status request, and every subsequent ping would be lost to a seat nobody reads.
- **Report a localhost or loopback health check in plain text, never inside a code span.** Measured: the Conductor message channel's firewall silently drops a message carrying a loopback URL in backticks; the identical text without them delivers. The send reports success, so the loss is invisible from the sending end — a delivery failure wearing the costume of a formatting nit.

**New eval harness** `run_ping_label_evals.py` (CI-wired). It greps `plugins/flow/skills`, `plugins/flow/docs` and `research/` for the contract's trigger phrase and asserts the convention verbatim at every file it finds, parses the status set **out of the shipped text** to assert it is exactly four, and runs its own mutation selftest on every run rather than behind a flag — because a harness of substring checks over prose can degrade to "clean" without failing.

- **A limit-killed worker is never rendered as parked.** The digest's gated-vs-silent test consults the **transcript first**, not git: a worker whose last assistant message is a session-limit kill is `SILENT` regardless of its branch state, and only once that is ruled out does the branch/PR/`plan:`-subject shape mean "parked". An unreadable transcript renders *"parked or dead — can't tell"*, never `GATE`. This corrects a rule that shipped in review: a worker that pushes `plan:` commits and then dies on the session limit has a byte-identical git signature to a parked one, so the git-only version resolved the ambiguity toward the reassuring answer on exactly the case that cost two days.

**Honest limit, unchanged by this release:** nothing mechanically enforces the opener. Flow does not wrap worker messages, so the eval pins the *brief* and the contract docs, not a worker's actual output. The convention is stated where a worker reads it and measured nowhere after that.

**Breaking changes:** none. The label is additive — a message without it still arrives, it is just not scannable. Consumers who do not run an orchestrator seat are unaffected.
