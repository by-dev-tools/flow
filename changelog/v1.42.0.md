## v1.42.0 — `add-entry` takes untrusted text off the command line entirely (SAFETY)

**Status:** PLANNED — plan at the human gate, not yet implemented. This file claims the version
mechanically (a duplicate version is a duplicate filename, which git reports as a both-added
conflict) per FB-0103; it is rewritten with the shipped detail at ship time.

Systemic follow-up to v1.41.0's narrow, per-site shell-quoting fix. `manifest-triage.py`'s
`add-entry`, `record-attempt` and `waive` stop accepting `--finding`/`--resolution` as raw argv;
the text arrives only as a file path written out-of-band by the Write tool, so there is no shell
construct — and therefore no text-based boundary — for a crafted finding to break out of. The argv
flags are removed rather than deprecated, with a named rejection arm that exits 2 and spells the
replacement: an unsafe path that remains callable is a convention, not a fix (FB-0108).

See `dev-docs/feedback/FB-0108-*.md` and the plan block in `dev-docs/plan.md`.
