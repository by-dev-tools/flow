## v1.42.0 — SAFETY: `add-entry` takes untrusted text off the command line entirely (FB-0108)

Systemic follow-up to v1.41.0's narrow, per-site shell-quoting fix. That fix made the *current*
call sites safe; this one makes the *next* one safe by construction.

**The unsafe door is closed, not joined by a safe one.** `manifest-triage.py`'s `add-entry`,
`record-attempt` and `waive` no longer accept `--finding`/`--resolution` as raw arguments. The text
arrives only as `--finding-file`/`--resolution-file`, written out-of-band by the Write tool, so the
bytes travel file → `open()` → `str` and never enter a shell word. The removed flags stay declared
purely to exit 2 with a message naming the replacement — flow's own history docs contain literal
`--finding "…"` invocations and agents read history docs, so a stale copy-paste gets taught the new
spelling instead of an argparse usage dump. There is no flag, env var or fallback by which argv text
reaches the manifest again.

**No heredocs, and no stdin.** Every *text-based* boundary can appear inside the text. v1.41.0's
first attempt used a quoted heredoc, which is escaped by a payload containing a bare `FLOWEOF` line —
measured, not theorised. Separator sentinels fail identically. And stdin is not offered because from
a Bash call the only way to feed it is a heredoc or a quoted string.

**Also in this release:**

- **`scratch-path --name …`** — one place resolves producer scratch paths, inheriting
  `_repo_scratch`'s worktree fallback, `.flow`-directory symlink refusal, `mkdir -p` and self-ignore
  instead of re-deriving them in prose. Every producer site resolves its paths through it
  (18 call sites), and an eval asserts no `--finding-file` placeholder exists that no
  `scratch-path --name` resolves in an adjacent block. It **unlinks** each target before printing, so a
  planted symlink is removed rather than written through (CWE-59, write side — the half a read-time
  check cannot reach, since the Write lands before any read).
- **The non-empty guard moved into the engine.** `--finding-file` exits 2 on a missing, empty,
  non-regular or symlinked file. Stronger than a shell guard, which can be stranded in the wrong Bash
  call — and it catches "the Write tool never ran", which no shell guard sees.
- **Producers now check their exit status** (`|| exit 1`) at every site — 16 `add-entry`
  invocations, each with its own redirect and guard. An unchecked failure
  appends nothing, so Step 7a.5 would classify an *empty* manifest and open a **non-draft** PR over an
  unresolved blocker — a gate going quiet exactly when risk is highest (FB-0062).
- **An allowlist, not a denylist.** Every append to the manifest path in `ship/SKILL.md` must be
  produced by a `manifest-triage.py` subcommand, paired with the positive that such appends exist and
  number what they should. **Scope: `ship/SKILL.md` only** — not appends in another file, from a script
  it invokes, or built from a runtime variable.
- **Newlines — and only newlines — collapse** in a finding, including a lone `\r`. Tabs and double
  spaces pass through byte-identically.

**Verification: attacked, not read.** 14 payloads run through `/bin/sh -c`, each designed against
*this* mechanism — command substitution, quote breakout, heredoc-delimiter collision, the manifest's
own fence marker, the parser's own field separator, a symlink to a private key, path traversal, control
bytes, a 100 KB finding. Red arms prove the tests can fail, each matched to the composition carrying
its hazard. The symlink case asserts the key sentinel reaches no output stream, not merely that the
exit code is 2. A producer's CALL 1 and CALL 2 blocks are **extracted from `SKILL.md` on disk and executed**
as separate processes — not retyped into the harness — because dogfooding would exercise the
installed plugin (FB-0107) and a retyped twin goes green on shipped-text drift. That
extraction immediately earned its place: it caught a single-block producer shape that could
**never** succeed, because `scratch-path` unlinks its targets and the Write tool cannot run
between two lines of one shell block.

**Every producer now prescribes the invocation, not the line.** All 13 remaining bullets that showed a
rendered manifest line (`[security] <finding> — needs: …`) now show an `add-entry` call. A rendered line is
something an agent hand-composes, which bypasses `--kind`/`--needs` validation and puts untrusted text back
in a shell word. `test_producer_lines` is tightened accordingly: the template form is now **forbidden**, not
merely tolerated alongside the validated one.

**Two pre-existing parser defects found and deliberately NOT fixed here** (scope was the input path):
a finding containing the manifest close marker erases every later entry and flips the verdict to
`READY`; and the field separator can be forged, truncating what the human reads. Both in
`dev-docs/roadmap.md` § Next with measurements.
