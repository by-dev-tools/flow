## v1.65.0 — cheap worker reads, a workspace-vs-subagent rule, and routing by job fit

**The headline.** Flow's own measured token-efficiency audit (`dev-docs/research/2026-10-efficiency-audit.md`)
found three fixable gaps in how the orchestrator suite spends tokens. This release closes all three.

- **`dispatch_backend.py` gains a sixth, optional verb: `readSince {session} {cursor}`.** Measured:
  walking a worker's full history on every check was independently found to be the orchestrator's
  3rd-largest Bash-output category (62 calls, 105,385 characters over 22 days). A backend that
  doesn't configure it reports `absent` (not `invalid`) and the workflow still applies in full — it
  only loses the cheap path. `/flow:orchestrate` step 4 now states the cursor-first contract
  explicitly, with a concrete default query for the common no-backend case, rather than leaving the
  practice to be rediscovered as raw Bash habit.
- **`/flow:spawn` gains an unnumbered "Before Step 0: choose the primitive" section** — a measured
  three-row table (branch/PR/independent-ship → workspace; distinct installed-plugin state →
  workspace; read-mostly and single-turn → subagent), plus the nuance the audit's rule-of-thumb
  didn't carry on its own: a subagent's output lands directly in the calling session's own context,
  so on a long-lived seat it should still return a short, structured result rather than "explore
  broadly and report everything back."
- **"The fleet needs the capacity" is no longer a valid routing reason.** A live dispatch brief had
  downshifted one job's model tier to free capacity for a different, unrelated job — the mirror image
  of the already-forbidden "decline a worker to conserve budget." `/flow:spawn` step 2 now names this
  explicitly, and `research/orchestrator-field-manual.md` § 3 carries Ben's own priority verbatim:
  token efficiency matters, but overage or a tier change is his call to raise, never flow's to propose
  as a routing workaround (FB-0140).

**Also recorded, not shipped as a fix:** resuming this branch after a 25-day merge-ping gap on #179
surfaced — again — the silent active-block-reorder hazard a clean rebase produces in `dev-docs/plan.md`
(the same class #179 itself documented fixing for its own rebase). Caught this time by the
`extract-criteria.py` check before any gate ran against the wrong PR's criteria; no plugin behavior
changed as a result, so it isn't a line item above.
