## v1.66.0 — `/flow:post-merge` is now `/flow:retro`

**The headline.** Ben reaches for this skill as "the workspace retro" — "post-merge" never
came to mind when he went looking for it by name, even though the name accurately described
*when* the skill runs. Renamed the skill (directory + frontmatter `name`) and every live
reference to it: `workflow-help`, `docs/workflow.md`, `/flow:land`'s caller text, `doctor`'s
skill-composition example, the `run_land_evals.py` / `run_merge_status_evals.py` /
`run_skill_composition_evals.py` live assertions, the `postMergeWaitSeconds` slot's description
text, and the canonical `research/2026-08-23-flow-cloud-workflow-plan.md`.

- **No deprecated alias.** Confirmed against Claude Code's own docs first: there is no
  author-definable skill-alias mechanism for plugin skills — "built-in aliases exist only for
  bundled skills and commands... you can't define your own." Straight rename, no migration
  period (FB-0141).
- **Historical records left untouched, deliberately.** `changelog/`, `dev-docs/history/`, and
  the "Shipped"/"Prior" narrative inside `dev-docs/plan.md` / `dev-docs/roadmap.md` § Now
  describe what was true when those PRs shipped, under the name the skill had then. Rewriting
  them would misrepresent history, not correct it — same principle as every other point-in-time
  doc in this repo.
- **Open backlog items fixed too.** `dev-docs/roadmap.md` § Next/§ Later carried several
  not-yet-picked-up items that named the skill by path (`skills/post-merge/lib/merge-status.py`,
  `/flow:post-merge` §4, etc.) — those are forward-looking triggers for future work, so they'd
  have silently misdirected the next session to a directory that no longer exists. Fixed; the
  explicitly-labelled "✅ SHIPPED... v1b design record" block was left as a historical/design
  retention, same reasoning as above.
- **Filed, not built:** a roadmap § Next entry for a doc-currency gate gap found in
  `byamron/portfolio` (relayed, since that workspace's contribution queue couldn't survive its
  own archival) — `/flow:ship` Step 5b's version-gate fallback has no good answer for a project
  with no real release-versioning discipline (a Vite-scaffolded `package.json` stuck at `0.0.1`
  either blocks every ship or, once satisfied once, never catches real staleness again). What
  the fallback should actually be is a judgment call with more than one defensible answer, so
  it's a roadmap item for its own plan, not a line item in this PR.

**Breaking changes:** yes. `/flow:post-merge` no longer exists — there is no alias and no
deprecation period (Claude Code has no author-definable skill-alias mechanism for plugin skills,
confirmed before deciding; this repo's own guidance is to ship the straight rename rather than
invent one). If you have a saved shortcut, a script, or any automation that invokes
`/flow:post-merge` directly (interactively or via `claude -p "/flow:post-merge ..."`), update it
to `/flow:retro` — the old command will read as unrecognized once your install picks up this
release. The `postMergeWaitSeconds` config slot's **name** is unchanged (only its description
text now says `/flow:retro`), so existing `flow.config.json` values for that slot keep working
with no action needed.
