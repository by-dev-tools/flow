## v1.66.0 — push-further never blocks, and the marketplace gains deep-dives

**The headline.** The push-further lens now says outright that it never holds up a PR, and that a
missing quality the surface doesn't call for (a settings form without fidgetability) is not a
finding. An eval pins it. The marketplace also lists a second plugin, **deep-dives**, for
hands-on design sessions where you make every call.

- **Push-further stays general, with a loose link to Puckett.** Its questions are prompts, not a
  checklist, and they fit any surface: a pipeline, a doc or a data view as easily as an interaction.
  When the surface *is* an interaction, Josh Puckett's eight lenses are offered as an extra frame
  to draw on where they fit. Nothing is graded against them.
- **The same rule in lens-experience's Lens B**, which runs push-further at the brief and plan gate.
- **New eval `run_push_further_evals.py`** (CI-wired). It checks that the lens's
  output labels are exactly its three non-blocking buckets (an allow-list, so a new label fails
  whatever it's called), that no bucket reaches the BLOCKER line of staff-review's triage while every
  bucket is still routed, that review-brief treats push-further as non-blocking, and that the lens
  states its never-block rule, plus Lens B's labels and rule. Every run also mutates each check and
  fails if any of them stays green, so a check that can no longer fail is caught.
- **deep-dives** ([by-dev-tools/deep-dives](https://github.com/by-dev-tools/deep-dives)) is listed in
  this marketplace from its own repo. First skill: `/deep-dives:puckett-uncommon-care`, an
  interactive session on one interaction. It runs without flow. Install with
  `/plugin install deep-dives@flow`.
- **Provenance reads flow's marketplace entry by name.** `/flow:ship`'s `## Flow run` rows
  read the marketplace version from `plugins[0]`. With two plugins listed, that would report
  deep-dives' version as flow's if the entries were ever reordered. Pinned by a paired eval.

Breaking changes: none.
