## v1.56.0 — the prose was selected; now it is read, fingerprinted, and not cut in half

v1.55.0 taught `/flow:audit-coverage` to **select** behaviour-bearing prose. Three things it left behind had one shape — a gate that reads less than it reports, and says nothing.

> **Selection without instruction is not a fix.** The evidence arrived and the reviewer's own instructions said to ignore it.

- **The reviewer is now told which prose is surface.** The evidence block prints `[audit-coverage] DOC-SURFACE` naming every doc-shaped file the slot selected, and both reviewer stages carry an exemption keyed on that line. It deliberately carries **no `WEAKENED` token** — every weakening says less was read than usual, and this says more was. **Absent the line the suppression stands**, so an ordinary README or comment edit is still not a behaviour.
- **A `.md` edited after `/flow:staff-review` now invalidates the rigor marker.** The fingerprint was computed through `sourceFilePatterns`, which matches no `.md` path at all — deliberately, since that is what keeps a docs-only PR off the source-touching branches of `/flow:ship`. Measured on #172: **0 of 13** changed `.md` files were in the fingerprint, including the two shipped `SKILL.md` files that PR existed to change. Dev-tracking docs stay **out** on purpose: `/flow:ship` Step 5 rewrites the plan doc in the same commit as the code, and a gate that always fires is one people learn to click past.
- **Wrapped criteria reach the reviewer whole, and a block that ends early says so.** `walk_extract` kept only each bullet's **first physical line**, and ended the block entirely when a continuation line opened with a bold span. Measured on #159's plan: **1,143 → 5,831 characters** across the same 12 criteria. The count never moved, which is why nothing caught it. A block that stops at a terminator now reports the line and the item count; running to EOF stays silent.
- **`/flow:critique-plan`'s pin lint was the load-bearing half.** It had its **own copy** of the block scan, carrying both defects, so fixing the shared reader alone would have left it reading a fraction of every plan and reporting it clean. There is now one collector with two readers. Its pin matcher also stopped missing `run_*_evals.py` — `\b` treats `_` as a word character, so `eval` inside this repo's own artifact-naming convention never matched, and a fully pinned plan read as unpinned.

**Precision was measured for the first time, not re-confirmed.** The previous claim — a wording-only prose change returns `No issues flagged.` — was true and carried no information, because the doc suppression fired before any judgment happened. With the exemption live: **zero findings in 3 of 3** wording-only runs, and the same file plus **one added rule flagged in 2 of 2**. Recall on the same case: **40% / 60% / 60%**, union **60%**.

**Two honest limits.** The union has sat at 3-of-5 across five runs and two prompt revisions, and the latest three miss the *same* two gaps — union two passes when they are cheap, but **do not read a stable union as completeness**. And `DOC_BUILTIN` is three directory names (`skills/`, `agents/`, `rules/`) matched anywhere in a path, not "every shipped prose surface": it does not match `docs/` or `README.md`. Set `behaviorBearingDocPatterns` if your deployed prose lives elsewhere.

**New:** `plugins/flow/lib/doc_patterns.py` (one definition, two readers) · `walk_extract.collect_items` · `[audit-coverage] DOC-SURFACE`.

**Breaking changes:** none to any output contract. Two behaviour changes worth knowing before you upgrade: a `.md` change under `skills/`, `agents/` or `rules/` (or your `behaviorBearingDocPatterns`) now invalidates a rigor marker that previously survived it, so `/flow:ship` may route a prose-only post-review edit to the draft manifest where it used to read "ok" — that is the fix, not a regression. And criteria that were silently truncated now arrive in full, so a plan with wrapped bullets will feed `/flow:verify-build` more text than it did before.

**Note on v1.55.0:** it shipped without a changelog entry. This file does not backfill it; `dev-docs/history/2026-09-30-audit-coverage-reads-behaviour-bearing-prose.md` is its record.
