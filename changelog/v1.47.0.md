## v1.47.0 — `/flow:audit-coverage` gains a source-tree input mode

The coverage reviewer could only ever look at a **diff**. That is the wrong input at the one moment its judgment matters most: when a prototype has been approved and a plan written, but nothing has been executed yet — so there is no diff, and nothing reads the prototype's code at all.

- **`/flow:audit-coverage <path>` now audits a source tree** instead of a diff. Same reviewer, same judgment, second input. Point it at an approved prototype (a file or a directory) and it checks the same question it always has: for each user-perceptible behavior, would any declared `**Spec-walk:**` criterion cause someone to test it?
- **`/flow:audit-coverage` with no argument is unchanged** — still the workspace diff, still the `/flow:ship` Step 2 path. Diff-mode output is byte-identical to v1.45.0's, measured, and the eval suite pins the mode gate as a provable no-op rather than trusting the claim.
- **A source tree that cannot be read is `SOURCE-UNRESOLVED`, never `SKIPPED`.** Missing path, path outside the repo, empty walk, zero readable bytes — all route as "I never looked" (decision-required), never as "I found nothing to audit". If you named a path, an empty result means the path is wrong, not that the work is covered.
- **New eval harness** `run_coverage_source_mode_evals.py` (48 checks, CI-wired), including a positive-control run against a real 60KB prototype with ten known-undeclared behaviors — and a negative control on the probe itself, because a check that can only return "clean" is not a check.

**Breaking changes:** none. The new mode is entirely argument-gated; a project that never passes a path sees no change whatsoever.
