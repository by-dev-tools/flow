# v1.63.0 — a captured still frame reaches the human in the chat and in the PR

Closes roadmap **D7** § Next, "Inline chat images as the always-available route for still frames".

## Added

- **`captureBackend`** — an OPTIONAL host adapter that turns an HTML page flow authored (the gate-1
  prototype, the merge-gate walkthrough) into a PNG. **One** verb, `screenshot`, with a CLOSED
  `{url}`/`{out}`/`{width}`/`{height}` vocabulary in which **all four are required** — a template
  that cannot be told a size produces two identical frames under two different size labels, which is
  a picture that lies. No `{selector}`/`{wait}`: flow photographs a whole page it authored itself,
  and a template that could choose *what* to photograph would let config decide what the frame
  claims. Shell operators are refused rather than escaped, reusing
  `dispatch_backend.render_template` so there is no third copy of the policy.
- **`chatImagePath`** — an OPTIONAL directory for the ONE frame embedded in the gate-1 chat message.
  A slot rather than a hardcoded scratch path: the obvious candidate is ignored only through
  `.git/info/exclude`, which is local to one clone, so a consumer would have neither the directory
  nor the ignore rule (FB-0085). Flow prints a note, and `/flow:doctor` reports, when the configured
  path is not git-ignored.
- **`artifact-handoff.py frames --source auto|captures`** — the `## Before / after` section built
  from this PR's committed frames under `<dir of visualHistoryPath>/pr-frames/<branch-slug>/`. Same
  discipline as the record source: a row only for a path the named sha contains as a blob, inline
  images only for a confirmed-public repo, `/blob/` links otherwise. The per-PR directory **is** the
  own-PR guard — another PR's frames are never listed rather than excluded by a comparison.
  **`auto` falls back to the curated record when this PR captured nothing**, and the shipped call
  sites use it: a configured adapter must never retire a consumer's existing frames.
- **Alt text that says what the frame shows.** `capture` writes a small `frames.json` beside the
  frames holding the captured page's `<title>`; the renderer reads it back out of the commit with
  `git show <sha>:<path>`, so the PR body's alt leads with the surface rather than only naming a
  viewport. Degrades to the label when absent, and is never empty. Captions and alts both say
  **"first screen"** — a capture is one screenful at that viewport, not the whole page.
- **`artifact-handoff.py local-line --chat-image`** — one captured frame in the gate-1 message.
  Accepted only for `--kind prototype`: the frame is local and uncommitted, so the same syntax in a
  PR body is a broken image.
- **`/flow:ship` §5d** — captures and stages this PR's frames, gated on the same authoritative
  `visual_significant` verdict §5c and §7b read. **`/flow:ship` and `/flow:ship-spike` choose their
  frame source from the adapter's own exit code**, not from grepping a render. The capture targets
  `prototype.html`, **not** `prototype.presented.html`: the presented file carries flow's own
  click-to-pin dock, which is why the gate-1 line has to apologise for it in prose — in a still that
  dock is furniture a reviewer cannot distinguish from the design's own.
- **`capture_frames.py frames-dir`** — one composition of the per-PR directory, called by the shell
  that writes it and by the renderer that reads it back. It was briefly a shell literal plus a
  Python constant, which is the one contract both halves must agree on.
- **`/flow:doctor` Check 2.14** — WARNs on a malformed `captureBackend`, silent when the slot is
  absent. Like Check 2.13, it exists because the failure mode is invisible: a malformed template
  fails *open* to a hand-off that is still correct, so nothing looks wrong. It **calls** the
  engine's git-ignore predicate rather than re-implementing it, and that predicate is a tristate —
  "could not measure" (outside a repo, corrupt index, git absent) is never reported as "not
  ignored". `chatImagePath` being unset is reported as a supported configuration, not a warning: a
  warning that fires on a correct setup is how people learn to ignore warnings.
- **`evals/run_capture_frames_evals.py`**, wired into CI.

## Measured, not assumed

- A headless run prints `Failed to connect to the bus` to stderr on **every** invocation and still
  exits 0 with a correct PNG. So success is the **artifact** — PNG magic bytes plus the IHDR
  dimensions — never the exit stream.
- A raw URL pinned to a PR-branch sha that a squash-merge **discarded** still returns http 200
  (paired against `main`'s sha at 200 and an all-zeros sha at 404). Committed per-PR frames keep
  resolving after the branch is deleted at merge, which is why `/flow:land` does not prune them.
- A page without a UTF-8 charset renders `✓` as `âœ“`. Such a page is **refused before capture**.
- Repo growth: **~20 KB per visual PR**, permanently.

## Changed

- Schema **38 → 40 slots**. Five shipped surfaces carrying a stale slot count were corrected, along
  with two eval harnesses; two of those were found by `run_merge_status_evals.py`'s own fan-out guard
  rather than by grep.
- `run_dispatch_backend_evals.py` § 7's shared-lib sweep count **12 → 13**, and its inventory comment
  corrected — it claimed "5 shared libs" while asserting 12 over a directory holding 6.
- `run_preview_backend_evals.py` and `run_artifact_handoff_evals.py` now **derive** their count pins
  from the directory instead of hardcoding a literal.

**Breaking changes:** none. Both new slots are unset by default, and unset is a correct, fully
supported state: no image syntax is emitted anywhere and every hand-off is byte-identical to
v1.60.0's — pinned by `test_unset_is_byte_identical` against literal expected strings rather than
against the renderer itself.
