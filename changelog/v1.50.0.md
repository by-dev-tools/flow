## v1.50.0 — a slash-command argument never touches a shell again

If you pass a path to `/flow:audit-plan`, `/flow:critique-plan`, `/flow:review-brief` or `/flow:audit-coverage`, that path used to be **pasted into a shell command and run, at render time, with no permission prompt**. Not quoted-and-run — pasted. `$ARGUMENTS` is not a parameter the host hands to a shell; it is a macro the host expands into the whole skill body *before anything parses it*, and it is not shell-escaped. Claude Code says so about itself, in the message it prints when asked to import a Gemini command: *"Claude Code's `$ARGUMENTS` substitution doesn't [shell-escape], so importing would let typed arguments inject shell commands."*

This release closes it, with one rule applied everywhere rather than four careful call sites.

- **The prose rule.** A slash-command argument now appears exactly once per skill, **in prose**, under an `## Argument` heading — never inside a shell block. Render-time blocks run argument-less, and the value reaches a program only through a channel no interpreter parses: either the reviewer's own `Read` tool, or a file the model writes with `Write` whose **fixed literal** path the block reads. The full mechanism, with the two tiers and when each applies, is in `docs/workflow.md` § "Skill arguments: the prose rule".
- **Why not just quote it better.** Because quoting cannot work when substitution happens first. `"$ARGUMENTS"` still admits `$(…)`, a backtick, and a closing quote — measured, 3 of 5 payloads escape. Nor can a delimiter: flow shipped a quoted-delimiter heredoc for exactly this, and a payload whose second line equalled the delimiter escaped it and executed, after which the guard printed a clean-looking refusal **after** the command had already run. Every text boundary can appear in the text.
- **A second bug, same mechanism, live on `main`.** `$0`–`$9` are substituted by the same pass, which makes every shell positional and awk field reference in a skill body a placeholder. `$0` maps to the *first* argument token, so **`/flow:ship <any argument>` was corrupting ship's own provenance block** — the `## Flow run` rows that exist specifically so you can tell which version of flow actually ran your pipeline. Fixed in `ship`, `doctor`, `contribute` and `verify-build`. Shell positionals are now spelled `${1}`; awk fields `$(0)`, because **awk has no brace form and `${0}` is a syntax error** — the obvious fix silently breaks awk while looking correct.
- **A lint that cannot pass by deletion.** `run_arg_safety_evals.py` is CI-wired and checks every shipped skill. It proves its own instrument first — rendering the *unfixed* form and asserting a filesystem canary **is** created, aborting if it is not, because a test that can only return "clean" is not a test. (The harness this replaces certified this very RCE as safe, by modelling the argument as an environment variable instead of substitution.) Every "no placeholder in shell" assertion is paired with a positive that the skill still accepts and still acts on its argument.

**Two limitations, stated rather than implied.** `/flow:critique-plan`'s deterministic pinning lint can no longer run against a *named* plan file — the plan-critic has no way to execute it, so the block prints its own scope and a named file routes to "treat pinning as UNCHECKED, not clean" instead of a lint that read the wrong document. And `/flow:audit-coverage`'s source mode is mechanical when a caller (`/flow:ship`) supplies the path and judgment-based on direct invocation, where it now emits a required `WEAKENED · FILTERS-ADVISORY` line; its directory walk needs a shell the reviewer deliberately does not have. Both are named in the skills themselves and routed to the roadmap.

**Breaking changes:** none to any output contract. `/flow:audit-coverage`'s source mode reads its path from `.flow/audit-coverage-arg.txt` rather than the argument directly; direct invocation with a path still works, via the reviewer's own read, and says so in its output.
