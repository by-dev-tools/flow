## v1.45.0 — the orchestrator skill suite

Four new agent-invocable skills for driving several worker workspaces from one seat, plus the two config slots that keep them host-agnostic.

- **`/flow:orchestrate`** — boot or re-boot an orchestrator seat: re-derive live worker state from the backend, sweep open branches *and* open PRs, find workers that have gone silent by last-activity rather than status, re-address the ping channel, load the gate policy.
- **`/flow:spawn`** — dispatch one worker: admission control, `model · effort · why` routing (floored for `sensitivePaths` work), the dispatch brief, the workspace. Records each routing decision so the policy can be tuned against evidence rather than memory.
- **`/flow:handoff`** — rotate the seat: flush durable currency, externalize anything that exists only in the outgoing sandbox, hand over a brief that is mechanically checked for references the successor cannot reach, archive-safety verdict.
- **`/flow:gate`** — four-axis plan-gate classification, merge-gate classification, the ships-or-paperwork pre-check, escalation formatting with a return address. **Classifies and formats only — it never merges, and no setting enables delegated merges.**

**New config slots (schema 34 → 36).** `dispatchBackend` — five command templates you supply, so no host CLI is named anywhere in the plugin. Placeholders are a closed set and there is deliberately **no `{message}`**: a brief or a status line is agent-composed prose, so message bodies travel as a *path* and unsafe values are refused rather than escaped. `sensitivePaths` — globs marking work that must not auto-approve and must not route down, with shape-based defaults (secrets, auth, migrations, published schemas, CI); your project's own gate machinery goes in your config, not in the plugin.

**Also:** `/flow:doctor` Check 2.12 validates the adapter at setup (silent when unconfigured, WARN never FAIL when malformed). Three new CI-wired eval harnesses. The dispatch-brief template in `research/2026-08-22-conductor-orchestration.md` §10.2 corrected from the quoted `--message` form to `--message-file`.

**Breaking changes:** none. Both new slots are optional; every existing config resolves exactly as before, and a project that never orchestrates sees no change.
