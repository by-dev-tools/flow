## v1.49.0 — `/flow:audit-coverage` enumerates before it judges

The coverage reviewer has never once reported a gap that was not real. What it does do is miss real ones, unevenly — 10 of 10 on one run, 5 of 10 on the same input, 2 of 5 on another. This release attacks that, and the shape of the fix is a **split**, not an addition: the single pass was doing three jobs at once (find the behaviours, match them against the declared criteria, suppress weak findings), and the suppression rules that make it precise were also being applied to the finding half, where they only cost recall.

- **Two labelled stages, one judgment.** Stage 1 enumerates every user-perceptible behaviour with the suppression rules explicitly scoped *off* — in that stage the only error is omission. Stage 2 matches each one against the declared criteria using the existing, already-tuned judgment, verbatim. The matching half is unchanged; nothing was added to it.
- **Measured, not assumed — and the two input modes gave different answers, so they are reported separately.** In **source mode**, on a 60 KB prototype with 10 documented undeclared behaviours: mean recall **65% → 82%** across 4 before-runs and 5 after-runs, distributions not overlapping, union across runs **80% → 100%**. In **diff mode**, on a 5-gap case: **recall did not move — 3-of-5 before, 3-of-5 after (n=3)**, the same two missed both times. Nothing here is a diff-mode recall gain. **Precision stayed perfect in both** — zero false positives across all 15 runs. And **82% is a floor rather than a point estimate**: two runs flagged a real gap the reference case's own documented list never carried, and it was deliberately not added to the scoring key, because a key fitted to the outputs it scores measures nothing.
- **What the diff-mode zero bought instead is where the failure now lives.** Both residual misses were *enumerated and then dismissed* — the inventory lists them, and the `COVERAGE MAP` marks them `covered`. So the bottleneck is the matcher's "any criterion covers it, even loosely" rule, not an enumerator that never looked. Before this release a miss and a thorough pass were indistinguishable from outside; now a miss has a cause you can point at. That is the change's value in diff mode, and it is observability, not recall.
- **A clean result is now falsifiable.** The output carries the enumeration and a one-line `COVERAGE MAP` giving Stage 2's verdict on *every* behaviour, not just the flagged ones. Previously a run that noticed 6 of 11 behaviours produced output indistinguishable from a thorough one; now you can see what it looked at.
- **A deterministic change inventory, in diff mode** (so it takes no part in the source-mode numbers above). One row per hunk, computed by `git` rather than judged, that Stage 1 must account for — anything it cannot classify lands under `UNACCOUNTED` instead of vanishing. Each row is tiered by its relation to the plan: **`POST-PLAN`** means the hunk landed in a commit *after* the plan was last edited, so no declared criterion *can* cover it. That is the shape of most measured misses — behaviour added during `/simplify` and `/flow:staff-review` arrives after the Spec-walk is written.
- **Three new outcomes that are weakenings, never skips.** `INVENTORY-UNAVAILABLE` (no checklist could be built), `PLAN-PREDATES-BRANCH` (the plan was never touched on this branch, so the *whole* diff is undeclared), and a warning when the plan doc holds **multiple** `**Spec-walk:**` blocks — because only the first is read, and it can belong to a different PR entirely. Each says a clean result below is weaker than a normal one rather than equal to it.

**Known limitation, measured and worth reading.** On a project whose behaviour lives in **markdown** — a plugin made of prompts, for instance — this gate does not see it. `sourceFilePatterns`/`EXCL` exclude `.md`, so on one recent PR **4 of 63 changed files reached the reviewer** and an entire new shipped skill was invisible. Widening that is a contract change for every consumer and collides with the evidence cap, so it is scoped as its own work; see the roadmap. In the meantime: this is a completeness gate over the subset of your diff that matches `sourceFilePatterns`, not over your diff.

**Breaking changes:** none. Output gains two sections above the existing `ISSUE` / `AUDIT SUMMARY` / `No issues flagged.` shape, which is unchanged and is still what `/flow:ship` Step 2 routes on. Every skip and unresolved outcome still returns its fixed line as the entire response.
