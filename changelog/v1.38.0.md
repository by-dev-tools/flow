## v1.38.0 — 2026-09-03

**`/flow:ship-spike` now audits its own skips — the skip-heaviest path in the workflow was the one path that audited none of them.**

- **The gap.** `/flow:ship` invokes five reviewers and then `/flow:audit-skips` over the result. `/flow:ship-spike` invoked exactly one, `/flow:verify-build`, and never called the skip auditor at all — a fact its own prose stated outright. A merged spike PR shipped with five stages skipped (preflight, `/simplify`, staff-review, verify-build, memory) and no record that any skip was checked against anything. Same recurring class as FB-0082 (this gate silently inert for eight versions), FB-0085 (rules that never loaded), FB-0077 (a composition satisfied by deleting its call site): **a gate that does not fire where it is most needed.**
- **What spike mode may skip, and what it may not.** "The code is disposable" is a real rationale and it reaches exactly two stages — `/simplify` and `/flow:staff-review`. It does **not** reach `/flow:security-review` (the code is disposable, the *commit* is not: a key hardcoded in a spike stays in git history after the spike is deleted) or `/flow:accessibility-review` (flow is deliberately moving the human gate onto prototypes, so an a11y flaw in an approved prototype propagates into the real PR as an endorsed *pattern*). Both now run in spike mode, and both self-skip on a doc-only / non-UI diff, so the common spike pays one early-exit each. `/flow:audit-coverage` stays skipped for a structural reason — a spike declares a research question, not a Spec-walk — and that claim is mechanically verified against the plan file.
- **A mode is not a skip reason.** The engine now REFUSES `spike`/`tiny` as a skip reason for every stage except `/simplify` and staff-review (`SHOULD-RE-RUN`, auto-resolvable) — a closed two-member allowlist, so `verify-build` (the behavioral gate) and any stage added later are covered by the rule rather than by whoever remembered to list them. A mode-declared blanket skip is unauditable by construction — mode is a plan declaration, so the gate would be accepting the very claim it exists to contest. The two stages that legitimately skip by mode still return `NEEDS-JUDGMENT`, resolved against the plan's declared mode; that mode is now surfaced to the auditor as `context.plan_mode` **evidence** and deliberately not promoted to a mechanical verdict, because a first-match read of a plan doc carrying one `**Mode:**` line per PR block can be confidently wrong in the failure-open direction. A well-formed spike still rules clean — spike mode does not draft over its own declared mode.
- **Spike PRs have no draft manifest, so an unresolved finding pauses instead.** `auto-resolvable` → re-run the stage and re-audit once. Anything else — decision-required, a `LEGITIMATE · manifest:` entry there is no manifest to file, or any error shape — halts and hands the choice to the user, exactly as the toolchain-absent verify-build skip already did, with the decision recorded in the spike's history entry. Never a silent proceed.
- **Two security fixes found by this PR's own review pass.** (1) **CWE-59, second half:** the stage-handoff block guarded the scratch *directory* against being a symlink but not the *files* written inside it — a repo can ship `.flow/` as a real directory containing `skip-audit-stages.json` as a symlink to `~/.claude/settings.json` or `.git/config`, and the heredoc would follow it and truncate the target. Reproduced end-to-end against a hostile fixture, then fixed in **both** handoff copies (`/flow:ship` and `/flow:ship-spike`) and pinned. (2) **Prompt injection into the skip auditor:** the new plan-mode evidence field echoed a line from the plan doc verbatim into the forked auditor's prompt — and that auditor is exactly the gate an adversary would want to soften. It now reports a closed vocabulary (`spike`/`tiny`/`other`/null) and no attacker-controlled text at all.
- **Also fixed:** `/flow:ship-spike` instructed `Skill("flow:verify-build")` while its `allowed-tools` omitted `Skill` — a composition the runtime can reject, which is FB-0082's shape one layer up. A new repo-wide lint now fails CI for any skill that emits a fenced `Skill()` call without declaring the tool (prose mentions excluded, so `/flow:doctor` — which documents the idiom it lints — correctly passes). New `preflight` stage in the audit engine; the handoff↔engine join is now pinned behaviourally, so a stage row neither handoff's engine recognizes can no longer classify as an ordinary judgment call while auditing nothing.

**Breaking changes:** none. Existing spike PRs keep working; they gain the audit and two reviewers that self-skip on the typical docs-only spike.
