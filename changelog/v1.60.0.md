## v1.60.0 — the two ephemeral artifacts can be served at a URL a phone can open

v1.59.0 made the hand-off honest about a file nobody else can reach. This makes it optionally reachable — as a host adapter, without naming a vendor anywhere in the plugin, and without ever removing the honest line.

> **The constraint that reshaped this came from the host CLI's own `--help`, not from an assumption.** *"Each workspace has one preview URL; setting a different port keeps the URL."* So two artifacts cannot hold two live links: a second port would silently re-point the first while leaving it looking valid — the exact defect v1.59.0 removed.

- **New `previewBackend` slot (schema 37 → 38)** — an optional host adapter modelled on `dispatchBackend`. Three verbs (`serve` / `publish` / `unpublish`), a **closed** `{dir}`/`{port}` vocabulary, refuse-rather-than-escape, and a template carrying a shell operator rejected outright *with the fix named*. **Unset by default, and unset is a fully-supported state**: every hand-off then renders exactly as v1.59.0 did, byte-for-byte, pinned by an eval that writes the expected strings out rather than importing the format string.
- **No `{url}` placeholder, deliberately.** The URL is the adapter's *output*, read from `publish`'s stdout. A template that could compose the URL would let project config decide what the hand-off **claims**, which is the one thing a hand-off must not delegate. Zero URLs, two different URLs, or an `http://` URL are each a stated refusal — never a guess.
- **The URL is additive; the local line is the floor.** Measured twice: a served preview's backend dies when its workspace sleeps while the URL *registration* survives. A link that looks live and is dead is worse than a path honest about being local.
- **The URL is a bare autolink; the path stays a code span.** Deliberately opposite — a code span renders as untappable monospace on a measured touch client. The rule, written into the engine so the two are not later "harmonised": **render it the way the reader can act on it.** They look inconsistent and are not; the reader's available action differs.
- **Who can open the link is stated next to the link**, not only in docs — the person deciding whether to forward a URL is the one who needs to know.
- **Flow never publishes a port nothing is listening on.** The predicate is validated against a *real* server on a real port before its negative is trusted.
- **`/flow:doctor` Check 2.13** WARNs on a present-but-malformed template, and is silent when the slot is absent. It exists because this feature fails **open and invisible**: a broken template falls back to the honest local path, so nothing looks wrong while a project that believes it configured a preview silently never serves one.

**MEASURED IN THIS REPO, PAIRED.** An unauthenticated fetch of a served page returns `http 401` + *"Sign in to view this preview."* (30 bytes); the same file via a local control returns `http 200` (86 bytes) with the content present. So the sign-in gate is **real**, not merely documented — and the pairing is the point, since a 401 alone could not distinguish "gated" from "broken".

**Flow's own `flow.config.json` now sets the slot.** A slot unset by default is a feature that runs **nowhere** — including here — and is therefore never exercised; that is the FB-0085 shape. `flow.config.json` is project config, so naming a vendor there is fine while the same name in `plugins/flow/**` would not be. `serve` calls a `.claude/bin/` script, because backgrounding needs exactly the shell operators the adapter refuses — which is what `validate` tells an author to do.

**Three existing checks caught this PR, and each is a mechanism working rather than a surprise:** `run_dispatch_backend_evals.py` § 7's exact artifact count went 11 → 12 the moment the new lib landed in `plugins/flow/lib/` (its own comment predicted that, and it means the new lib inherits the existing host-literal sweep instead of getting a duplicate); the `N slots` fan-out fired at four shipped surfaces; and v1.59.0's own region-scoped no-client guard fired on this PR's rationale prose, which was reworded rather than the guard loosened.

**One guard was narrowed, and not weakened.** That same guard also fired on the *rendered* hand-off, because both interpolated values legitimately contain a vendor name — the audience string and the URL's hostname. Neither is a claim about a client's *behaviour*; one is a measured access fact, the other a real address. The guard is now scoped to flow's own authored wording, and paired: a client name in flow's own prose still warns. A warning firing on every correctly-served hand-off is how people learn to ignore warnings.

**Two defects review caught that no test did**, both of the shape this workstream exists to remove. `<url>/<file>` was documented in four places and implemented in none — the hand-off passed `publish`'s raw **directory** URL, so a reader got an index listing and *both* artifacts got the identical link, collapsing "one URL, two stable paths" into one ambiguous one. And a failed staging step still published, handing over a URL for a file that was not there. The eval could not see the first because it handed the renderer an already-composed URL: a pin one layer below the claim. The composition now lives in a sourced helper and the eval drives that helper.

**The serve block became a sourced helper, because the reviewer was right and I was not.** The first cut put 40 lines in `/flow:ship` and told two other skills in prose to "run ship's block" — and `ship-spike`'s instruction had already drifted *below* the fence it modified, so a top-to-bottom reader ran the render with the URL empty. The same-Bash-call constraint I had treated as an argument against a helper is the argument for one: sourcing satisfies it by construction.

**New:** `plugins/flow/lib/preview_backend.py` · `plugins/flow/skills/ship/lib/serve-preview.sh` · `plugins/flow/evals/run_preview_backend_evals.py` (CI-wired, 16 case groups) · `/flow:doctor` Check 2.13 · `.claude/bin/flow-preview-serve.sh` (project-dev infra, not shipped).

**Breaking changes:** none. With `previewBackend` unset — the default, and every existing consumer — behaviour is byte-identical to v1.59.0.

**Residual, stated rather than buried:** a reviewer **without** workspace read access gets nothing from the link, and the local line is all they have. That is **inference, not measurement** — the device testing was one account on its own workspace, and a second viewer has never been tested. It is a standing reason the local line is not optional, and it is recorded in roadmap D7.
