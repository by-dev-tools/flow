## v1.59.0 — a hand-off that names a local file says so plainly, and the committed frames render in the PR

Ben was reviewing from a phone. A gate that hands over a sandbox-local path has not asked anyone to look at anything — and a merge gate that asks a human to look at a *picture*, then links them to an HTML file's **source**, has not either.

> **The thesis, and the trap.** A hand-off must not claim what it cannot back. Option 2 is the half that can *reintroduce* the defect it fixes: a hand-composed image URL that is subtly wrong renders as a **broken image**, and nothing downstream would catch it.

- **`## Before / after` renders the committed frames in the PR body.** New `skills/ship/lib/artifact-handoff.py frames` — a projection of the **commit**, not of the session: it reads the committed `visualHistoryPath` record, requires the newest entry's branch to equal this PR's, and emits a row only for a frame the named SHA actually **contains**. Not "is in the index": the predicate asks `git cat-file -e <sha>:<path>`, the same ref the URL names, so the two cannot disagree.
- **Inline images only for a confirmed-public repo.** Measured as a pair, 2026-10-03: an unauthenticated `raw.githubusercontent.com` fetch is `200` for a public blob (11,699 bytes) and **`404`** for a private one (14 bytes). So everything other than a confirmed-public repo — private, `gh` absent, `gh` erroring, a `--repo` that disagrees with the checkout — **fails closed** to `/blob/` links, which an authorised viewer can open on any client. A wrongly-private verdict costs a missing image; a wrongly-public verdict costs a broken image *and* a false claim.
- **Every hand-off naming an uncommitted local file says where it can and cannot be opened, and names no client.** Four prose sites across `ship`, `ship-spike` and `prototype` now call `artifact-handoff.py local-line` instead of composing a string. Research § 6 Q1/Q2 — what the iOS app does with a session-produced HTML file — are **open**, so "iOS cannot open this" would be an unverified completion claim *and* wrong in the sync-to-a-laptop case.
- **"No frames, and here is why" is a first-class output.** Seven stated reasons, each carrying the same caveat the full-value case carries (GitHub shows that file's *source*, not the rendered page). This is the branch flow's own every ship takes, and the likeliest consumer branch.
- **`/flow:ship-spike` gets both fixes.** It is a second hand-off surface for the same two artifacts; leaving it would ship a contradiction between them. Its `## Before / after` sits after `## Recommendation`, not after `## Summary` — **one rule** ("the first thing the human wants to look at"), two positions, because a spike's deliverable *is* its question and answer.
- **`skills/ship/lib/md_safe.py`** — the markdown-safety policy for text the pipeline pastes into a PR body but does not author. One definition, two readers (`render-test-plan.py`, `artifact-handoff.py`). They had not merely duplicated it: the second copy passed `<`, the HTML-comment opener, so **one body carried two escaping policies**.
- **Flow's own `uiSurface:false` self-claim is corrected** at its two live sites (`schema/flow.config.schema.json`, `ship/SKILL.md` §5c). Flow has been `uiSurface: true` since **v1.24.0**, and §5c additionally still called the visual-history entry shape unvalidated, which the roadmap has recorded as VALIDATED for releases. Point-in-time records (CHANGELOG, handoffs, research) are deliberately untouched, as are the many correct references to `uiSurface:false` as a *consumer* state.

**What flow cannot dogfood, stated rather than glossed.** All four entries in this repo's own `dev-docs/visual-history.html` are inline CSS/SVG reconstructions, so `visual-history-assets/` does not exist here and **every flow ship takes the no-frames branch**. The frame branch is driven against a temp git repo, and `--selftest` was proven **mutation-sensitive** — neuter the committed-asset check and it goes red, naming the break — before any quiet result from it was trusted.

**Four defects the reviewers found in this PR's own work, each an instance of a rule already written down here.** They are listed because the disciplines that caught them are the transferable part, not the fixes:
1. **A three-line render pasted into a markdown table cell** — the placement Decision 5 had itself rejected as "the single worst place to render" this material.
2. **A measurement that could only return one answer**, inside this PR's own eval harness: the coherence case guarded on `flow:test-plan-provenance`, which is `pr-coherence.py`'s *subcommand* name rather than its marker, so the guard never matched and **both arms ran unstamped**. The fixture is now produced by driving the real renderer.
3. **A mutation test passing for the wrong reason** — after the escaper hoist, the mutant died on `import md_safe` and exited non-zero *without running*, so "non-zero" no longer distinguished "caught" from "never started".
4. **An over-broad read-back guard that would have blocked this PR's own correct body** — `--forbid` is a plain substring test, so a bare `{{` also rejects a body quoting a Handlebars/Jinja/Vue template. Narrowed to the two marker prefixes.

**SECURITY.** `/flow:security-review` found one BLOCKER: the emitted frame path was the single value in the engine that **no** escaping policy touched (`label`/`alt` and *rejected* paths were all neutralized), so a committed frame whose filename embedded a newline plus markdown rendered the attacker's lines as live markdown in the body — potentially a forged `## Test plan` heading above the real one, the section `pr-coherence.py` keys on. Now percent-encoded, which also subsumes the space/paren cases and, unlike an angle-bracketed destination, survives a line ending. Threat model stated honestly: the precondition is a *tracked* file with control characters in its name, authored by a collaborator with commit access — **low severity**, fixed because an unneutralized sink in a published artifact should not exist. Three further fail-open nits closed: a bare-backtick path span, a visibility guard that let an absent slug satisfy its own slug-match, and `sys.path` growth per call.

**ACCESSIBILITY.** An empty `alt` is markdown's *decorative* signal, so a screen-reader user at the merge gate was told nothing was there — in the one section deliberately moved to the top of the body for the reader who most needs the text. `insert-visual-history.py` defaults a figure's label to `""`, so this arrived without malice. Captions and alt text now carry a fallback chain, never render `****`, and are never announced twice.

**MEASURED ON A REAL IPHONE, mid-ship (2026-10-04), and it changed one thing.** A page served without a charset *header* leaves the browser to guess, and Safari on iOS falls back to Latin-1 — a `✓` rendered as `âœ“`. `python3 -m http.server` sends no such header, and that is what flow's own launch recipe serves `.flow` with. The audit came back asymmetric: `render-report.py` and `visual-history-skeleton.html` already declared UTF-8, but a **prototype is authored by the agent** and nothing required it — while `/flow:prototype` Step 8 injects the glyph-bearing annotation layer into exactly that file. So the one page a human is asked to *approve* had no guarantee. `/flow:prototype` now requires `<meta charset="utf-8">`, pinned. Also confirmed from that client: a `raw.githubusercontent.com` image link opens fine, which is option 2's mechanism verified on the device that motivated it.

**The section omits itself when there is no visual surface.** Found by running this pipeline on its own change: the slot was unconditional, so a PR touching no UI file would have published "No frames to show: …" — the right output for a *visual* change with no committed frames, and noise on the majority of PRs. Both surfaces now read the same shared visual-significance verdict that §5c and §7a already read.

**New:** `skills/ship/lib/artifact-handoff.py` · `skills/ship/lib/md_safe.py` · `evals/run_artifact_handoff_evals.py` (CI-wired, 17 case groups) · roadmap `### D7 — Reachability`.

**Breaking changes:** none to any output contract. Two behaviour changes can alter what your PR body looks like: a visually-significant ship now carries a `## Before / after` section (or one line saying why it does not), and every PR-body read-back now rejects an unreplaced renderer slot — if you publish a body containing `{{rendered by` or `{{provenance` verbatim, the read-back will stop the hand-off. That is the gate working.

**Held, not shipped:** option 1 (`conductor preview set`, a sign-in-gated preview URL) is PR B, blocked on measured iOS answers rather than built against assumed ones. Until it lands, gate 1 is honest and still unactionable from a phone — recorded in roadmap D7 so the gap is not mistaken for a design choice.
