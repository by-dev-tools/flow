## v1.39.0

- **Harvested lessons survive an ephemeral workspace (FB-0101).** The lesson-contribution queue lives in user-scope storage (`contributionsQueuePath`), which is correct on a persistent machine but is destroyed at teardown on a cloud workspace — taking every queued lesson with it, unread. `/flow:ship` and `/flow:ship-spike` gain **Step 4c.iv**: `harvest_lesson.py flush` writes full records to a repo-local `.flow-lessons/` (committed, so git carries them) and emits a **bounded** manifest for the PR body. The split is load-bearing — a queued record is ~1.6 KB against GitHub's 65,536-char body cap, so inline records overflow at **~37**, i.e. exactly when the queue has accumulated longest. Manifest rows are ~104 bytes (~600 fit). `/flow:contribute` gains a fallback drain input that discovers flushed PRs **cross-repo** via `gh search prs` (verified to index PR bodies and reach private repos); the local queue always takes precedence.
- **Orchestrator seat close-out (FB-0101).** Harvest only runs at ship time, and the orchestrator never ships — so lessons at the coordinating seat were structurally unharvestable. `dev-docs/workflow.md` now instructs that seat to write feedback entries directly, resolved through `flow.config.json.feedbackPath` (never a hardcoded filename). An instruction, deliberately not a mechanism.
- **SAFETY — scoping and hardening found by `/flow:security-review` before ship.** The flush publishes **only the current project's** records (the queue is cross-project by design, so an unfiltered flush would have committed one project's slugs, branches and internal doc paths into another's possibly-public repo). Lesson text can no longer forge the `flow:lesson-flush` markers or escape the `<details>` block. Session ids are hashed and no absolute machine path reaches a PR body. `git add` no longer uses `-f`, so a repo that gitignores `.flow*` is respected rather than overridden. `/flow:contribute`'s cross-repo discovery is constrained to `--author "@me" --merged` and reads the merge commit, never a fork ref — without that, any PR under the same owner could have fed an unattended drain.
- **New eval harness** `run_lesson_flush_evals.py` (34 checks, CI-wired), including a fixture sized to the *measured* real-world record mean so the overflow it asserts is the one that actually occurs.
