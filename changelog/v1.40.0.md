## v1.40.0 — 2026-09-06

**Append-only docs become one file per entry, and no reader can silently degrade to "no doc" any more.**

- **`historyPath`, `feedbackPath` and `changelogPath` now accept a DIRECTORY** holding one file per entry — the shape that stops concurrent PRs colliding on a shared insertion point. Both shapes work: the schema defaults stay single-file, so an existing project changes nothing until it wants to. `bootstrap.sh` scaffolds directories for new projects.
- **New `plugins/flow/lib/resolve-doc-slot.sh` — one shared, LOUD doc-slot resolver.** Every reader used to inline `[ -f "$X" ] && echo "$X" || echo "(no ... doc at $X)"`. `[ -f ]` is false on a directory, and the fallback was silent, so a misconfigured slot was indistinguishable from a project that legitimately has none — the FB-0082 class. Five surfaces would have broken (three reviewer preludes, `/flow:land`'s CHANGELOG check, and `referenceGlob`); five more carried the same latent bug on slots this release does not repoint. All ten are fixed, not just the breaking four.
- **`changelogPath` is finally declared in the schema** (33 → 34 slots). `/flow:land` had been reading it for several releases while it was absent from the schema, so consumers could not discover it and it silently fell back forever.
- **`/flow:land` fixes:** the CHANGELOG-currency check no longer becomes a silent no-op on a directory-valued slot, and its roadmap/plan/history sweep uses `grep -r` — plain `grep` on a directory contributed no matches, so the history half dropped out silently while the other halves still matched.
- **`dev-docs/reserved-feedback-numbers.md` is gone.** With one file per entry, a duplicate FB number IS a duplicate filename, which git reports as a both-added conflict — mechanical and unmissable, where the old registry was a free-form log git merged happily. Claiming a number is now pushing the entry file. `/flow:land`'s `clear-reservation` subcommand was removed with it, rather than left behind as a permanent silent no-op.
- **New eval `run_doc_slot_resolution_evals.py`** (CI-wired), with negative and positive assertions paired so that deleting a reader fails the check just as reverting it does.

**Breaking changes:** none for existing configs. Every slot's default is unchanged and every reader resolves file-or-directory, so a project that never set these slots behaves exactly as before. Two notes if you *opt in* to directories: (1) add the feedback directory to `referenceGlob` (e.g. `core-docs/*.md,core-docs/feedback/*.md`) — the feedback corpus is a reference document for `/flow:critique-plan`, and it would otherwise drop out silently; (2) `/flow:land`'s `clear-reservation` subcommand no longer exists.
