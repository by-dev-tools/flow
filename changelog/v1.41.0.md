## v1.41.0 — 2026-09-11

**A declared acceptance criterion can now be too vague to mean anything, and flow catches it — closing the seam `/flow:audit-coverage` left open.**

- **New `vacuous-criterion` manifest kind.** `/flow:audit-coverage` catches a behavior change with NO declared criterion (under-declaration). It could not catch a criterion so vague it plausibly covers the hunk anyway — "Rate limiting works correctly" satisfies coverage, then `/flow:verify-build` judges it PASS against equally vague narration. A new deterministic heuristic (`skills/verify-build/lib/criterion-specificity.py`, stdlib regex — never an LLM judgment) runs in `/flow:verify-build` Step 3 and flags any criterion with no observable predicate: no named output, state, value, or error path, just a generic "works" / "correctly" / "as expected" claim. Each flagged criterion routes to the existing draft manifest as a `[vacuous-criterion]` entry (10th producer kind), same `declare + fence` resolution shape as `coverage`.
- **Precision-favored by design.** A missed vacuous criterion is an accepted residual; a false positive on every well-written plan would get the gate routed around. The escape hatch (`CONCRETE_SIGNAL_RE`) suppresses the flag on any digit, quote, backtick, or named-observable verb/noun anywhere in the criterion.
- **Distinct from `/flow:critique-plan`'s `walk-pin-lint.py` (FB-0068), and now genuinely composes with it** — that lint asks, at plan-critique time over the whole document, "is a verification *method* named?"; this asks, at extraction time over the active Spec-walk block only, "is the criterion's own claim falsifiable?" A pin-marker annotation (`<claim> → verify: <method>`, the convention every Spec-walk checkbox in this repo already uses) is stripped before judging, so pinning a vague criterion no longer launders it past the check. See `docs/workflow.md` § 10.
- **New eval harness** `run_criterion_specificity_evals.py` (40 checks, CI-wired), including cases that specifically exercise the escape-hatch AND-NOT branch and the pin-marker interaction rather than only cases that never reach either.
- **SAFETY — the new manifest bullet captures untrusted plan text safely.** `/flow:security-review` flagged that a plan-authored criterion embedded verbatim in a shell argument could break out of the intended string if it contained a quote/backtick/`$()` — the common case, not an edge case, since well-formed criteria are expected to contain them. A first fix (a quoted heredoc) closed that vector but opened a narrower one — a criterion containing a line equal to the heredoc's own delimiter terminates it early, reproduced empirically. Fixed by capturing the criterion via the Write tool into a scratch file (no text delimiter to collide with at all) and referencing it through a double-quoted command substitution. One pre-existing site (`status-surface`) carries the original shape; the interface-level fix across all producer sites is tracked separately (`roadmap.md` § Next).

**Breaking changes:** none. Additive `metadata.vacuous_criteria_found` field on the verify-build findings buffer (`schema_version` unchanged); `manifest-triage.py`'s `KIND_COPY`/`KINDS` grow from 9 to 10.
