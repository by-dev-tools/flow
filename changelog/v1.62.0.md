## v1.62.0

**Writing `**Visual-walk:** N/A` to be explicit no longer flips the verdict to *visually significant*.** Being clear was punished; omitting the block was rewarded. (FB-0132)

- **The bug.** The Visual-walk override keyed on `block_count >= 1` and never read the block, so `**Visual-walk:** N/A — no UI in this change` set `visual_significant: true`. `/flow:ship` §7a then demanded a rendered walkthrough **and** a visual-history entry for a diff with no UI — neither of which can be produced — while omitting the block entirely gave the correct verdict.
- **The fix keys on a DECLARED denial, not on an empty block.** New `heading_declares_na()` and a shared `declared_na` field in `walk_extract.py`, read by `visual-significance.py` and by `/flow:verify-build` §5a (which now skips capture with an explicit `[§5a] skipped: Visual-walk declared N/A`, never silence). A **bare** `**Visual-walk:**` with no assertions deliberately still forces: §5a assigns that shape its own meaning ("capture the primary/launch state only"), so suppressing on emptiness would have retired a documented behaviour by reinterpreting it.
- **A deferral or a redirection is not a denial.** `None, will fill in later`, `N/A — TBD`, `N/A — deferred`, `N/A — awaiting design`, `N/A — in the next PR`, `N/A — see Figma`, `N/A — mockups attached` and `N/A — covered by #456` all keep forcing — the first five say *when*, the rest say *elsewhere*, and both mean a visual surface exists. Getting this right took **three** versions of the guard, and the third was caught by this release's own staff-review: the marker list did not contain the word `deferred`, so the plainest spelling of the class still suppressed. The accept/reject table could not see it because every row it had hit a marker the list already contained — an instrument validated only against its own vocabulary. 55 rows now, 22 of them sharing no token with the previous regex.
- **A heading that *looks* like a denial but isn't read as one now says so.** `**Visual-walk:** N/A for this PR` and `N/A — TBD` previously produced output identical to a bare block, so an author who wrote a denial was told "plan declares a Visual-walk block" and then asked for a walkthrough they cannot produce. You now get a warning naming the line and which reading it took (`defers` / `redirects` / the token ran into prose) plus the shape to write instead. It classifies, and never quotes your plan text back into the gate's prompt.
- **One counter-intuitive rule, now documented rather than discovered:** naming a visual artifact in the reason reads as a redirection *even when you negate it*, so `N/A — no frames needed` and `N/A — nothing to capture` keep forcing. Write why the surface is absent (`N/A — backend only`) instead. `plan-discipline` states this explicitly, and 14 of its examples are pinned against the parser so the doc cannot drift wider than the code again.
- **`plan-discipline` now publishes the convention it was matching authors against.** The skill told authors Visual-walk is "N/A under `tiny`" and never said what shape to write. It now states the sanctioned form (`**Visual-walk:** N/A — <reason>`), the exact token set, and the two shapes that deliberately do *not* mean it.
- **SECURITY — an explicit `N/A` can't put plan text into the skip-auditor's prompt.** The new branch originally forwarded the walk parser's warnings the way its two neighbours do, which would have routed the **happy path** — a correctly authored `N/A` — through a prompt-injection carrier for the first time (the neighbours are abnormal plan states, where the warning text is the operator's remedy). Two carriers were measured: the malformed-checkbox warning interpolates each bad line unescaped with no cap, and the multi-block warning interpolates the heading **untruncated**. Both reach `/flow:audit-skips`'s forked reviewer — the gate that decides whether skipped stages were legitimate. The passthrough is gone; the one remedy that path still owes an author ("a later block holds your real assertions and only the first was read") is reported as a block **count**. Pinned by `evals/security/test_plan_text_not_quoted.py`, which asserts over the real engine's stdout and refuses to report a pass unless restoring the passthrough makes it fail.

**Breaking changes:** none. A plan that previously got a spurious visual-deliverable demand from an `N/A` block now gets the verdict it declared; nothing that correctly forced before stops forcing. New `declared_na` key in `extract-criteria.py` / `extract-visual-states.py` JSON output — additive, and meaningful for `Visual-walk` only.
