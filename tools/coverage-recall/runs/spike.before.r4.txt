Claim:
> "Clicking an element while commenting mode is on opens a comment editor pinned to that element → verify: manual click-through in a browser."
> "A modifier-click (or equivalent escape hatch) passes the click through to the underlying page so links and interactive prototypes still work while commenting is on → verify: manual check."

Hunk: `annotation-layer.html` — `INLINE`/`walkList`/`buildWalk()`/`walkStep()`/`walkDepth()`/`focusWalkTarget()` (file ~lines 442-511), the `Shift`+Arrow branch of the capture-phase `keydown` handler (~1117-1125), the plain `ArrowUp`/`ArrowDown` widen/narrow branch and the `Enter`-to-commit branch (~1127-1143), the `focusin` target-setting listener (~1148-1154), and the editor hint text `⇧↑↓ walks elements, ⇧←→ widens/narrows` (~346). Suggested: Add a criterion covering keyboard targeting — Shift+↑/↓ steps elements, Shift+←/→ widens/narrows, Tab+Enter comments on the focused element — with a manual keyboard-only pass as the verification.

ISSUE 6 · Undeclared change

Claim:
> "An unreadable/corrupt overlay file degrades to the read-only report rather than crashing the renderer → verify: manual check with the overlay file temporarily truncated."

Hunk: `annotation-layer.html` — `saveWarned` / `save()` (~396-406): on a `localStorage.setItem` throw (quota, or storage blocked in private mode) the overlay announces once `"Comments could not be saved — this browser is blocking local storage. Why uncovered: Checked criterion 13 — its subject is an unreadable *overlay file* degrading to a read-only report, an injection-time failure, not a runtime storage refusal. Checked criterion 2 (persistence works and defaults on — the happy path; its verification is "toggle off, reload"), criterion 8 (the analogous degraded path for the *clipboard*, explicitly scoped to the clipboard API), and criterion 10 (announcements on mode toggle / count change — this message is neither). No criterion would cause anyone to run the overlay with storage blocked, so a silent-loss regression here passes every declared check.

Suggested: Add a criterion mirroring the clipboard-fallback one: with local storage blocked (private mode or quota), commenting still works and a visible/announced warning says comments will not persist.
