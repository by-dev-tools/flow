## 2026-09-06 — Fragment the append-only docs to one file per entry, and kill the silent doc-slot fallback (v1.38.0, FB-0100/FB-0101) — SAFETY

**Branch:** `conductor/fragment-append-only-docs-one-file-per-entry` · **SHA:** [this commit] · **Version:** v1.37.0 → v1.38.0

**What was built.** `dev-docs/history.md` (3408 lines), `dev-docs/feedback.md` (1402) and `CHANGELOG.md` (656) became `dev-docs/history/`, `dev-docs/feedback/` and `changelog/` — **245 fragments, one file per entry** (106 / 84 / 55) plus a README each. `flow.config.json`'s `historyPath`, `feedbackPath` and new `changelogPath` point at the directories. `dev-docs/reserved-feedback-numbers.md` was deleted. Every doc-slot reader was hoisted onto one new shared resolver, `plugins/flow/lib/resolve-doc-slot.sh`. `changelogPath` was declared in the schema (33 → 34 slots). New eval `run_doc_slot_resolution_evals.py`, CI-wired.

**Why (SAFETY).** Two failure classes, both observed rather than theorized.

1. **Merge conflicts.** An append-only doc has one insertion point, so every concurrent PR collides there. This was the dominant conflict source in the repo.
2. **Silent deletion.** A clean auto-merge can drop an entry with no conflict markers and a clean parse. The fragmenter found **two live instances in `main`** on its first run, neither previously noticed: `feedback.md` held a bare `### FB-0072:` heading whose body a merge had dropped (the real FB-0072 was 45 lines below; #80 wrote it, #83/#84/#85 each touched the region), and `history.md` held the same F11 entry **twice with different bodies** (#114 and #115 both added it, git merged both). Both survived CI, four staff-review lenses, `/flow:doctor` and the auditor for weeks — every gate was reading text that parsed fine. A merge can drop lines; it cannot silently drop a file.

This change adds a **new BLOCKER path** (the resolver's loud states, and `/flow:land` refusing to skip its currency check quietly) — hence SAFETY.

**Design decisions.**
- **Directory-valued slots + one loud shared resolver, NOT a generated rollup.** The rejected alternative was a generated-and-gitignored rollup that preserves `[ -f ]`. It fails on "what happens on a fresh clone before anything generated it": the readers are `!` bash preludes, so guaranteeing the file exists means generating it *inside* the prelude — three reviewers and `land` writing to the working tree during pure context resolution. If the generator fails (no `python3`, read-only FS), `[ -f ]` is false and the identical silent bug returns with more moving parts between cause and symptom. CI and fresh clones would have no rollup, so `/flow:doctor` would `[WARN]` on a *correct* path — readers do not stay ignorant, the knowledge just moves, plus a second artifact that can silently disagree with the first. Decisively: **it preserves `[ -f ]`, and `[ -f ]` is the defect** — it would fix `feedbackPath`/`changelogPath` while leaving `specPath`/`designLanguagePath`/`planPath` armed for the next person.
- **No committed rollup and no committed index.** Both recreate the exact conflict being removed (every entry appends a line). `ls` is the index, generated by the filesystem at zero conflict cost. Root `CHANGELOG.md` survives as a 3-line **pointer stub** — it holds no entries, so it is not a rollup — because it is the one file with an external-audience convention. *This specific call was not among the four the human answered; taken on the stated recommendation and flagged as trivially reversible.*
- **`plan.md` and `roadmap.md` deliberately untouched.** They are edited in place, not appended to; they feed the positional Spec-walk parser (`walk_extract.py`); and their single-document shape is what makes them readable as current state. Their conflicts are accepted.
- **No git union merge driver.** Tested and rejected upstream: GitHub ignores user-defined `.gitattributes` for PR mergeability, so it would resolve local rebases but not clear `CONFLICTING` on GitHub or let the merge queue batch. It is also unsafe on edit-in-place files — two branches editing one version headline silently produced *both* lines with no conflict, which is exactly the doc-currency corruption the Step 5b gate exists to catch.
- **Schema defaults stay single-file.** `historyPath` still defaults to `dev-docs/history.md`. Changing a default silently repoints every consumer who never set the slot. Directory is the *recommended* shape (what `bootstrap.sh` scaffolds), not the forced one; both resolve.
- **Damaged entries preserved, not repaired** (human decision, overriding the recommendation to repair). At MEDIUM confidence with a reversible and an irreversible option available, take the reversible one: preserving costs a duplicate file someone merges in thirty seconds, deleting costs content nobody can recover. Both are named in their directory READMEs and in the PR body so the judgment is scheduled rather than lost.

**Technical decisions.**
- **Byte conservation proved from disk by an independent tool.** `fragment.py` writes **verbatim** slices — deliberately un-normalised, because normalising trailing newlines would have made on-disk reassembly non-exact and reduced the check to "the tool agrees with itself." `reassemble.py` reads only the manifest and the files on disk, never re-deriving the slicing. All three reassembled bit-exact: history `8c46a482…a87374` (668,584 bytes), feedback `cc19e29d…fa075d` (231,638), changelog `2633d0b2…0b9565` (101,820). A second, separately-accounted pass then stripped inter-entry separators from 239 files (510 bytes), asserting every removed byte matched `[\s]*(-{3,}[\s]*)?`. **`reassemble.py` is deleted in this PR** — its only job was this proof, and leaving a rollup generator in the tree is how a committed rollup eventually happens.
- **Entry census on the identifier SET, not just the count.** Byte conservation cannot catch a heading swallowed into a neighbour's body — the bytes are all still there, in the wrong fragment. Census confirmed 84/55 identifier sets and a 106-heading multiset match, with the two known duplicates preserved.
- **Collision refusal is the default; known collisions are admitted one at a time** by explicit `--disambiguate <basename>`. There is deliberately **no global `--force`**: a blanket override would let a future migration paper over an *unknown* collision, which is the failure this tool exists to surface.
- **The mechanical check is paired in both directions** (`.claude/rules/general.md` item 3). Negative: no shipped `SKILL.md` carries a silent doc-slot fallback, scanned **repo-wide** rather than prelude-scoped — prelude-scoped would go green over a repo still degrading silently at the argv-construction sites. Positive: each of the 8 known preludes must still *resolve* its slot. Proven by experiment: reverting one prelude to the old form fails 3 checks, and **deleting the line entirely still fails 1** — so satisfying the detector by removing the feature is not available.
- **The checker scopes to executable lines.** Its first run flagged `land/SKILL.md`'s own explanatory comment (`# NOT [ -f "$CHANGELOG" ]…`). A checker that cannot tell an explanation from an occurrence pressures the author to delete the explanation to go green — satisfying the detector rather than the contract. `ci.yml`'s harness-join check already scopes to executable step lines for the same reason.

**Tradeoffs discussed.**
- **`referenceGlob` was the fifth breaking surface, and it was found by running `/flow:critique-plan` on this PR's own plan.** `feedback.md` *is* a reference document (`extract_session.py` skips only history/plan/roadmap by name), so fragmenting it would have dropped every FB rule out of the critic's context — and the FB-0082 zero-resolution warning would **not** have fired, because README/spec/workflow/design-language still resolved. Fixed by comma-splitting the slot into repeated `--reference-glob` flags (backward compatible). `dev-docs/**/*.md` was rejected: it drags in every point-in-time research and handoff doc.
- **`DEFAULT_REFERENCE_SKIP_NAMES` was a prohibition satisfiable by deletion.** It skips by *filename*; once `history.md` is a directory the entry matches nothing and silently stops protecting anything. Made directory-aware.
- **A first-cut fix WARNed on correctly-scaffolded fresh projects.** Dogfooding `bootstrap.sh` caught it: an empty doc directory is genuinely ambiguous (fresh scaffold vs. broken migration) and the first version confidently asserted one cause. Now `/flow:doctor` discriminates on the scaffolded README (bootstrap always writes it) and the resolver names both possibilities instead of guessing.
- **Deleting the reservations file is better, but not for the reason first given.** The honest objection is that a registry is a *claim-time* defense while a filename collision is *merge-time*. It does not survive contact: claiming is now *pushing the entry file* — the same early-push race detection with the entry as the artifact. And the registry recorded six renumbering incidents in its own audit trail, so it documented the cost rather than preventing it.

**Coordination note.** `/flow:land` changed in four places and a sibling dispatch is building a Notion surface hooked there: `:295` CHANGELOG-currency now uses `[ -e ]` + a loud else (was a silent no-op on a directory), the history sweep at `:253` uses `grep -r` (plain `grep` on a directory contributes no matches, so the history half of the sweep silently dropped out while roadmap/plan still matched — a partial result that looks whole), §6 clear-reservation was removed entirely, and the Project-context block now resolves history + changelog through the resolver.

**Lessons learned.** The strongest verification here was the one that could disagree with its author: `fragment.py` checking its own in-memory slices proved only self-consistency, and rewriting it to write verbatim so an *independent* reader could reassemble from disk is what made the accounting worth anything. Same shape as the eval's paired assertion, and same shape as `/flow:critique-plan` finding the `referenceGlob` gap that the plan — and the design decision it implemented — had both missed.
