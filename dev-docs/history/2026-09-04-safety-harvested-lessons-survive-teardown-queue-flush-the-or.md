## 2026-09-04 — SAFETY: harvested lessons survive teardown — queue flush + the orchestrator close-out (FB-0101, v1.39.0)

**Branch:** `conductor/spike-designmd-investigation-vercel-agentic-design-guidance` · **SHA:** (assigned at commit) · **Mode:** feature

**What was done (user-facing).** Three things, one root cause. (1) `harvest_lesson.py` gains a `flush` command; `/flow:ship` + `/flow:ship-spike` gain **Step 4c.iv** calling it, so a ship on an ephemeral host writes its queued lessons into the PR instead of losing them at teardown. (2) `/flow:contribute` Step 2 gains a third, explicitly-subordinate drain input that recovers those flushed records **cross-repo**. (3) `dev-docs/workflow.md` gains an orchestrator close-out section. Plus `run_lesson_flush_evals.py` (18 checks, CI-wired) and roadmap/§Exploration + AB.1b routing for the two sibling stores that are *not* fixed here.

**Why.** A `/flow:ship-spike` run on a Conductor cloud workspace (PR #140) harvested three flow-generalizable lessons and correctly warned that the queue was ephemeral. The human had already archived six workspaces that day without checking theirs. The queue defaults to `~/.claude/plugins/data/flow/contributions` — user-scope storage that is right on a laptop and destroyed at teardown in the cloud.

**The finding that reframes it, and the reason this is a correctness fix rather than tuning.** Flow's single-source protection (FB-0010/FB-0056) says a lone weak signal waits for occurrence #2. That premise requires a store that survives to *see* occurrence #2. On an ephemeral host it does not: `recurrence_count` is structurally pinned at `1` forever and `dedup`'s exit-3/exit-4 recurrence paths are unreachable. **So "drop, it's single-source" stops meaning *defer* and starts meaning *destroy*.** The guardrail's entire justification is a deferral it can no longer perform. The tempting response — lower the bar — treats a storage defect as a judgment problem; rejected.

**Design decisions.**
- **Fix the storage, not the bar.** `contributionsQueuePath`'s own schema text already says *"Override only to relocate the queue (e.g. onto synced storage)"* — the escape hatch was designed in and nobody set it.
- **Ride the PR, not a new store.** Committing the queue into the working repo would break FB-0059's cross-project contract (a consumer repo's queue committed to the consumer repo never reaches flow). The PR both survives teardown *and* crosses the boundary. Same reasoning canonical §4.3 used when it deleted the ledger's state role in favour of PR+label: prefer the substrate that already survives by construction.
- **Three stores, three scopes — deliberately NOT unified.** The queue is *cross-project* (fixed here); the harness-audit marker is *flow-repo-only* (git-backed; already filed as AB.1b, left there); the memory corpus is *per-project* at a harness-owned path and reads **0/30 on every fresh cloud workspace** — not degraded but wholly non-functional (routed to § Exploration). Forcing one substrate on three scopes would over-couple them for the appearance of tidiness. This was the explicit instruction and it is recorded so a future reviewer does not "tidy" it.
- **The orchestrator gets an instruction, not a mechanism.** The queue exists to carry a lesson across a repo boundary; the orchestrator already sits inside a flow checkout with merge rights, so it writes the feedback doc directly. A `/flow:harvest` skill would be the queue-management subsystem this work was told not to build, and the parallel learner FB-0059(f) forbids. **Tradeoff stated plainly:** those lessons skip confidence scoring, dedup and recurrence counting — acceptable only because the alternative is not *scored* lessons but *no* lessons, which is the status quo it replaces.
- **The orchestrator instruction resolves through `feedbackPath`, never a hardcoded filename**, and says so — a sibling dispatch is fragmenting `feedback.md` to one-file-per-entry, and the instruction must stay correct after that lands. It also states that if the slot resolves to a directory, the *fields* are the format and the file layout is not.

**Technical decisions / tradeoffs.**
- **Both preconditions were settled empirically before building, at the human's insistence — and one changed the design.**
  - *Cross-repo discovery:* `gh search prs` **does** index PR bodies and **does** reach private repos the token can read (verified live against `byamron/*`). So the flush is not capped to flow's own lessons and the cross-project contract survives. Caveat recorded in the skill: GitHub's search index is eventually-consistent, which is tolerable because the drain is periodic and the local queue covers the fresh case.
  - *Body size:* **this changed the shape.** Measured, not estimated: real records are ~1,596 B compact; GitHub caps a body at 65,536; PR #140's body was already 5,534 B — leaving room for **~37 records**, and 40 overflows. The original "dump records into the body" design would have failed *exactly* when the queue had accumulated longest. Split into committed-full-records (no ceiling) + a ~104 B/row manifest (~600 fit).
- **The eval caught a flaw in its own fixture.** The first draft used ~1 KB synthetic records, so the "inline would have overflowed" assertion silently did **not** hold at 60 records. Fixture resized to the measured real-world mean, with a comment recording the near-miss — an assertion that passes for the wrong reason is worse than no assertion.
- **`sanitize_tokens.py` assumes the origin project is not flow.** Discovered while rescuing: a full `scrub` rewrites the literal correct path `plugins/flow/skills/general/SKILL.md` into `plugins/<project>/skills/general/SKILL.md`. When origin == destination the project token is a literal, not a leak. `flush` therefore redacts only the genuinely machine-specific class (absolute window paths) and leaves the rest. Recorded in FB-0101 as its own finding.
- **The raw evidence windows are never emitted or committed.** ~61 KB each of transcript carrying private-repo names (`byamron/health-tracker`, `decisions/design-language`) — and this repo is public. Records keep `lesson_hash` plus the original basename instead. Pinned by an eval.
- **`dev-docs/contributions-rescue/` is superseded by the mechanism it motivated**, and its README says so. It carries an explicit deletion criterion and a guard that nothing may be taught to read from it.

**Staff-review found a BLOCKER that would have shipped a dead mechanism — recorded because the near-miss is the lesson.**
- **The flush manifest never reached the PR body.** Three compounding causes, all confirmed by inspection: `MANIFEST` was a shell variable in Step 4c.iv while Step 7 is a separate Bash invocation ~340 lines later (shell state does not persist); Step 7's body-assembly instructions never mentioned `flow:lesson-flush`; and the name **collided** with the *draft* manifest path, reassigned at three later sites. Net effect: the `<!-- flow:lesson-flush:begin -->` marker would never reach GitHub, so `/flow:contribute`'s `gh search prs "flow:lesson-flush"` would match nothing — **the entire cross-repo recovery path, the whole reason the flush is not merely a local directory, would have silently no-opped.** Fixed by persisting to `$FLOW_SCRATCH/lesson-manifest.md` (the cross-step idiom `triage.json` already uses), renaming to `LESSON_MANIFEST`, and adding an explicit Step 7 body-assembly bullet in both skills. **It would have passed every eval and shipped inert** — the evals tested the emitter; the break was in the wiring between two skill sections.
- **Three of four lenses independently flagged `git add "$FLUSH_DIR" 2>/dev/null || true`.** Silent failure there loses exactly what the feature exists to save while the body still advertises lessons that are not in the commit — verbatim the shape `.claude/rules/general.md` § Consistency discipline forbids. Now `git add -f` plus a positive assertion on the staged-file list, with a loud `⚠️` otherwise.
- **The empty-queue notice shared stdout with the machine-consumed manifest**, making `[ -n "$MANIFEST" ]` inert: on a re-ship of a branch whose `.flow-lessons/` already existed, the literal string `[flush] queue empty - nothing to flush` would be pasted into the PR body. Reproduced before fixing. Now on stderr, with the eval asserting **both** sides (`in stderr` **and** `stdout == ""`).
- **A negative assertion in the new eval was vacuous — in the file whose own docstring cites the rule against exactly that.** `check("raw transcript window never emitted", ".window.jsonl" not in r.stdout)` could never fail, because fixtures named windows `w7.jsonl`. Fixed by giving fixtures the real harvest shape, then **mutation-tested**: leaking the basename into a row turns the check red; restoring turns it green.
- **A newline in a model-authored summary split the markdown row and corrupted every row below**, and `|` was substituted (`/`) rather than escaped (`\|`), silently rewriting the lesson's own text. Both fixed in one `_md_cell` helper, with hostile-input fixtures.
- **Three of the four blockers were copy defects**, which is itself the finding. The `<details><summary>` line — a once-per-PR cost, outside the per-row budget — spent itself on a count and a path. All three real records truncated mid-word at 70 chars with no ellipsis, losing the contrast clause that *is* the lesson ("…not th"). Now word-boundary truncation with `…` at 110 chars, a `Record` column mapping each row to its committed file, and a summary line stating the stakes and that no action is needed at merge.
- **The deletion criterion was unfalsifiable.** "Delete if the flush carried zero lessons the local queue did not already deliver" depended on a number nothing produced — input 3 dropped duplicates without counting non-duplicates. `/flow:contribute` now prints `[drain] N of M flushed records were flush-only recoveries` into every contribution PR body. An unfalsifiable deletion criterion is decoration — the precise failure FB-0088 exists to prevent.

**`/flow:security-review` found a cross-project data-leak that neither the design nor four staff lenses caught — SAFETY.**
- **The flush would have exported the ENTIRE cross-project queue into whichever repo was shipping.** `_queued_records` returned every `status:queued` record regardless of `provenance.project_slug`, and Step 4c.iv runs in *every* project. Concretely: harvest lessons while working in private `health-tracker`, then ship an unrelated PR in a public repo, and that PR would commit health-tracker's project slug, branch names and internal `target_hint` doc paths into a public branch and paste their summaries into a public PR body. **The cross-project property that makes the queue valuable is exactly what made the flush dangerous** — and I built the flush without re-examining it. Fixed: `flush` now filters to the current project; cross-project drainage stays `/flow:contribute`'s job, which scrubs tokens first.
- **`git add -f` overrode the consumer's own `.gitignore`.** I added `-f` to defeat a hypothetical `.flow*` ignore — i.e. to force-publish into a repo whose owner had deliberately opted out. Removed; the flush now warns loudly and accepts that it cannot help on that host.
- **`_md_cell` escaped `|` but passed `<`, `>` and the literal marker string through.** The end marker is 30 chars, inside the 110-char summary budget, and ship Step 7 anchors its region replacement on it — so attacker-influenced lesson text could forge a marker and truncate or overwrite the real PR body region, or break out of the collapsed `<details>`. Not XSS (GitHub sanitizes), which is precisely why it was easy to miss. Now neutralized both ways, with evals.
- **`/flow:contribute`'s new cross-repo discovery was an unattended prompt-injection path.** `gh search prs --owner <owner>` matched *any* PR under the owner and then read `.flow-lessons/` from an arbitrary head ref — a contributor's fork for external PRs. Since `synthesized_rule` becomes edits and `target_hint` names the file to edit, anyone could have opened a PR on any public repo of the same owner and had an unattended drain propose edits to a widely-installed plugin's reviewer prompts. Dedup offers no defense: an attacker record has no local hash, so it classifies as a "flush-only recovery" and is accepted. Constrained to `--author "@me" --merged`, reading the merge commit rather than a fork ref, with an explicit never-relax note.
- **The honest read on sequencing:** I added a *cross-repo ingestion path* in the same change that added a *cross-project export path*, and evaluated each on its own. The composition — anyone's PR body becomes an edit proposal against a public plugin — only appears when you look at both together, which is what a dedicated adversarial pass is for and what the four craft lenses are not.

**Lessons learned.**
- **A guardrail's premise is part of the guardrail.** Single-source protection was never wrong; its precondition silently stopped holding when flow moved onto ephemeral hosts, and nothing re-checked it. Worth asking of every gate: *what does this assume about the environment, and is that still true?*
- **Recurrence is only counted along the axis the store happens to index.** The identical root cause was recorded a week earlier against the harness-audit marker (`history.md`, AB Step 1). Two subsystems, one defect, found independently — that pairing *is* the recurrence the bar wanted, and no mechanism could surface it because dedup works on `lesson_hash` within one store. Cross-subsystem recurrence has to be looked for by hand.
- **Evals test the unit; the wiring between sections is where a feature dies.** The 25 checks were green while the manifest could never reach a PR body — the break lived in the join between two skill sections, which no unit eval addresses. When a mechanism spans two steps, the thing to verify is the *handoff*, not either end.
- **A negative assertion nobody has watched fail is not a check.** The repo's own rule names this class, the eval file's docstring cites it, and the file violated it eight lines later. Mutation-testing a negative costs one minute and is the only thing that distinguishes a check from a comment.
- **Settle "cheap to verify" items before designing, not after.** One of the two confirmed the design; the other changed it. Deferring them would have shipped a mechanism with a latent ceiling at ~37 records.
