**Design decisions.**
- **Paired negative/positive assertion for the workflow.md fix**, per `.claude/rules/general.md` § Consistency discipline rule 3 (a negative alone — "workflow.md is excluded" — passes in two opposite worlds: the entry was removed, or the whole list was emptied). `test_always_loaded_excludes_workflow_and_keeps_the_rest` asserts both halves in one test. **Mutation-tested both arms, not merely asserted**: reintroducing the bug (workflow.md back in `static_paths`) turns the negative half RED (1 failure); emptying `static_paths` entirely turns the positive half RED (2 failures — CLAUDE.md and the rules glob); the restored code is green (0 failures). Reported here per FB-0104's own lesson ("a regression test never observed failing is a claim, not a test") rather than left as an unverified assertion about the test's own soundness.
- **Fence pairing is line-based, not a single open...close regex.** The first version used `^```(lang)\n(content)\n```$` (MULTILINE|DOTALL) and got ship's shell fraction wrong by several points. Root cause: `ship/SKILL.md`'s Step 7a.5 block has a closing ` ``` ` fence with trailing prose on the *same* line (`` ``` Because the attempt is recorded... ``) — not clean CommonMark, but real content. A regex anchored on "closer alone on its line" silently drops that pair and swallows everything up to the *next* real closer into the wrong bucket. Fixed by finding every line that starts (after leading whitespace) with 3+ backticks and pairing them positionally in document order — correct because markdown fences don't nest, so fence-marker lines strictly alternate open/close. Regression-pinned in `test_split_handles_closing_fence_with_trailing_prose`.
- **The pure/impure classification for `ship/SKILL.md` is a curated table keyed by heading text, not a keyword heuristic.** A regex over "git commit" would both over-fire (Step 2a's manifest writer touches git-adjacent scratch paths but never commits) and under-fire (nothing lexically distinguishes "this step hands off to a human" from prose). Read the whole file in full to classify each `## ` section by hand. A heading not in the table is `UNCLASSIFIED` with a loud warning, never silently folded into PURE or IMPURE — the same fan-out discipline as a hardcoded path list, applied to a classification table instead. `test_ship_sections_have_no_unclassified_headings` pins this: if ship/SKILL.md's steps are ever renamed or a new one added without updating the table, the eval goes red.
- **Two sections are classified AMBIGUOUS on purpose, per the task's explicit instruction not to force a bucket:**
  - **"1. Pre-flight"** mixes read-only gates with `git checkout -b` (a shared git-ref mutation) and the Step 1c mechanical fix-and-retry loop (edits real files). Neither action is in the IMPURE example list (`git commit`, `gh pr create`, body/draft writes, Step 8 hand-off) but both are real side effects with a plausible fork-boundary hazard.
  - **"4. Synthesize session feedback (two layers)"** is mostly judgment plus local doc/memory writes (PURE-shaped), but Step 4c.iv runs `git add` to stage the lesson-flush directory — a git-index mutation embedded in an otherwise-forkable section.
  - "Gotchas" and "Config slots" are reference material, not pipeline steps — labeled META and excluded from the pure/impure percentage denominator so they can't dilute the ratio.
