## 2026-09-16 — Spike: D1 §9.3 — is an auto-written technical plan good enough to anchor the machine gate?

**Branch:** `conductor/spike-93-auto-plan-quality` · **PR:** (assigned at open) · **Mode:** spike (the research doc is the deliverable; no plugin code was written to answer the question)

**Research question.** `dev-docs/handoffs/d1-prototype-first-gate.md` §9.3, rated LOW confidence: is an agent auto-writing a Spec-walk technical plan — after prototype approval, before any code exists — solid enough that D1's machine gate (and downstream `/flow:audit-coverage` + `/flow:verify-build`) have something real to check, or is the gate a rubber stamp?

**What was done.** No plugin code changed. Auto-wrote a design brief + a 13-item Spec-walk technical plan against `plugins/flow/skills/verify-build/lib/annotation-layer.html` — the handoff's own named "reference case" (§3 step 4), a real artifact with six rounds of genuine human review (FB-0076) and a real shipped staff-review pass (PR #49). Ran four independent instruments against that one auto-plan: the shipped vacuous-criterion checker (`criterion-specificity.py`, #148), a live headless-Chrome dry-read, a directly-spawned `flow:plan-critic`, and a directly-spawned `flow:auditor` reproducing `/flow:audit-coverage`'s own task framing with the prototype's real source substituted for a diff. Full account + evidence files: `dev-docs/research/2026-09-16-d1-auto-plan-quality-spike.md` and its two sibling files (`design-brief.md`, `auto-plan.md`, committed unmodified).

**Answer: MIXED.** 0/13 criteria vacuous (clean on the axis that checker polices) but 10 real, distinct behaviors undeclared (bulk/single delete, a second independently-persisted preference, pin-visibility toggle, panel open/close, per-row copy, a storage-failure warning path, Escape's branching, discard-on-empty-close, and — independently caught twice, once via the brief and once via the code — the whole keyboard-only interaction path). A clean vacuity score and a hollow coverage score, on the same plan, is the finding: they measure different things, and a plan can pass one while failing the other. `flow:plan-critic` also found 2 BLOCKERs (an internal incoherence where the plan's Files-touched section named a fictional path disconnected from the real approved prototype; a silently-dropped brief-mandated accessibility requirement). The direct `flow:auditor` claim-check found 2 more gaps neither mechanical checker (`criterion-specificity.py`, `walk-pin-lint.py`) can catch: a criterion testing a component the plan's own Scope explicitly excluded, and a verify-method vaguer than every sibling's.

**Why this path, not the skills directly.** Checked before assuming, not caveated after: this repo's installed plugin (1.29.0) is already measured (`dev-docs/history/2026-09-13-dogfood-version-provenance.md`) to resolve zero reference docs via `/flow:critique-plan`, so that skill invocation would have been indistinguishable from a reviewer that read no rules. `/flow:audit-coverage` needs a git diff and there is none pre-execution — but its judgment ("for each user-perceptible behavior change, check whether any declared criterion would cause someone to test it," its own `SKILL.md:130`) is diff-agnostic and transfers to a source tree with one substitution. Both direct-spawns reproduce the real reviewer's real task framing; neither is an invented rubric.

**Recommendation: proceed, but the fix is smaller than "add a fourth reviewer."** `/flow:audit-coverage`'s existing, already-tuned judgment — fed the approved prototype's source as an alternate input mode instead of a diff — caught most of the real gaps here; that is an input-mode addition to an existing reviewer, not new prompt-engineering surface. Two live options for whoever designs Phase 3 (not this spike's call, routed to Ben/orchestrator): (a) add that non-diff input mode and run it at the pre-execution gate; (b) accept coverage-hole detection only happens post-execution, and scope Step 6's machine gate as form/coherence-only with the completeness risk priced in. §9.3's confidence stays LOW — this spike did not flip it to HIGH, it confirmed the risk is real on one heavily-reviewed real prototype (n=1, stated plainly, not a general claim about auto-plan quality).

Per the orchestrator's direction, Phase 2 (building in parallel) is not blocked by this spike; only Phase 3 is. Flagged in the research doc; the handoff itself is out of this spike's scope to edit.
