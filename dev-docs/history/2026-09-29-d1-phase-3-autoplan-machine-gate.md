## 2026-09-29 — D1 Phase 3: the auto-written technical plan and its MACHINE gate
**Branch:** `conductor/track-b-d1-phase-3-autoplan-machine-gate` · **SHA:** see PR · **Version:** v1.54.0 · **FB:** FB-0125

**What was done:**
`/flow:autoplan` — after human gate 1 (prototype approval, v1.48.0), the technical plan is auto-written against the approved prototype and gated by machine on three arms. Plus `skills/autoplan/lib/gate.py` (the deterministic engine), the call site in `prototype/SKILL.md` § 10, the `/flow:review-brief` generalization that makes Arm C a composition rather than a build, `evals/run_autoplan_evals.py` (144 checks, CI-wired), and a new `walk_extract` field, `first_heading_line`.

**Why:**
§ 9.3's spike resolved **MIXED**, and MIXED is not "half good" — it is two findings about two different properties needing two different gates. Criterion *quality* measured clean (0 of 13 vacuous) and is **deterministic**, so it gets a hard red/green gate. Criterion *completeness* measured ~half the surface undeclared and is **best-effort LLM judgment**, so it gets a gate that can never pass on silence. Building one gate for both would have been wrong in one direction or the other.

**Design decisions:**
- **GREEN requires every arm to have RUN, evidenced, and returned nothing.** `/flow:audit-coverage` has perfect precision and 60–100% recall, so a flag is reliable evidence and silence is evidence of nothing. Every did-not-run path keeps a reason *distinct* from ran-and-found-nothing; collapsing them is the whole failure mode. This is FB-0121's contract arriving from a different direction.
- **The finder wins when two passes disagree.** Union, never intersect, never average. Given perfect precision, a gap seen once and missed once is a recall event, not counter-evidence — so 1-of-2 carries identical standing to 2-of-2, and the pass count is provenance that never touches the verdict. *The licence is the measurement, not the technique:* without the precision record, the same unioning amplifies noise, and the plan says so where a future reader who sees a false positive will find it.
- **Depth keys on the trigger's resolved `path`, not on `Mode`.** Keying on Mode left `spike` with no declared depth and let a `classic`-routed feature claim a depth with no prototype source to read. **Only `prototype-first` runs Phase 3** — `collapsed` and `classic` both keep `pre_execution_gate: "plan"`, so the human still gates those and there is nothing to replace. The machine gate is the counterpart of the *moved* human gate, one for one.
- **An unrecognized path refuses rather than defaulting.** A depth nobody declared cannot later be told apart from a procedure that did not run.
- **Arm C is `/flow:review-brief`, not a rebuild.** The handoff lists the fan-out harness as "used at Steps 3 and 6" — one harness, two call sites, and Step 3's shipped in Phase 1. Re-specifying it as a deliverable was caught at the plan gate.
- **Escalation pauses, never proceeds silently** (Ben, 2026-09-29, option (a)). It escalates worker → orchestrator → human. His reasoning, which is the transferable part: this is CLAUDE.md's existing *"third automatic gate on LOW-confidence assumptions"*, so the two-gate thesis holds — **the machine gate replaces routine plan approval, not every judgment.** No isolation scaffolding was needed: escalation is not a branch in `combine()`, so overriding it means deleting the rule rather than flipping a flag, which is the right shape for a gate.

**Technical decisions:**
- **Arm A reads the tools' OUTPUT, never `$?`.** Measured: `criterion-specificity.py` exits 0 while reporting a vacuous criterion, and `walk-pin-lint.py` documents *"0 for every lint verdict."* Neither has a red channel in the exit status. **The first draft cited `walk-pin-lint.py … → exit 0` as the evidence Arm A worked** — on a file carrying 591 unpinned checkboxes. That is FB-0010 item 4's corollary inverted: prefer an exit code *when the tool designed one*, and these deliberately did not.
- **Pinning is scoped to the active block.** `walk-pin-lint.py` is all-blocks by design; `extract-criteria.py` is first-block-only. Unscoped, Arm A is red forever in any repo retaining shipped blocks. A gate red for reasons nobody can fix is a gate that gets ignored.
- **Block identity keys on a line number, via a new field rather than prose-scraping.** `source_heading` is the identical string `**Spec-walk:**` for every unqualified block and `block_count` is a file-wide total, so the first draft's assertion on those passed whether or not the property held. The alternative considered was scraping the line out of the extractor's *warning text* — rejected as an instrument that breaks the next time that sentence is reworded — so `walk_extract` gained `first_heading_line` (additive; all 41 harnesses green).

**Tradeoffs:**
- **One escalation format, two engines.** FB-0075's renderer already ships as `manifest-triage.py render-decisions`, but it is draft-PR-shaped all the way down (`residual`, `class ∈ {ask,auto,blocked}`, `kind` vs `KIND_COPY`, copy that speaks in PR-readiness) and **no PR exists at this gate**. Composing would have meant fabricating PR-shaped classes or generalizing a shipped ship-path engine — new machinery on a path this PR is not touching. So the *wording* is unified (free, and the half the human experiences) and the *engine* is not, with an eval asserting the header still matches. Routed to roadmap D1f.
- **`/flow:review-brief` keeps its name** though it no longer reviews only briefs. Renaming a shipped, model-invocable skill breaks consumers for a cosmetic gain.

**What the reviewers caught, because it is the transferable part:**

Four of my own instruments reported a wrong answer on the way — a suppressed-stderr exit code read as a verdict, a `grep -oic` loop whose `|| echo` fired on exit 1, a header assertion that matched its own explanatory comment, and a check written as `X or True` — all four are in the harness or its comments rather than quietly fixed.
