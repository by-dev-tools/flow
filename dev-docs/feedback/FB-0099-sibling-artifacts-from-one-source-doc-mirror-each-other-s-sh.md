### FB-0099 — Sibling artifacts from one source doc mirror each other's shipped wording verbatim; a one-time personal-use prompt belongs in dev-docs, not the shipped plugin

**Date:** 2026-09-03
**Source type:** user direction (two decisions, same session, both following a `/flow:critique-plan` BLOCKER finding)

**What was said.** Dispatched to write a portable brief for auditing an *existing* repo's design-language doc against the five shape rules `dev-docs/research/2026-09-design-md-investigation.md` derived — a sibling worker was concurrently building `template/base/core-docs/design-language.md`, the scaffold for *new* repos, from the same source doc. `/flow:critique-plan` flagged that the brief's five-rule descriptions paraphrased the research doc instead of quoting it verbatim, on the exact passage the dispatch instruction named as the session's main coordination risk. Presented with three resolution options (match the sibling's shipped wording closely; make the wording character-for-character identical to the sibling's; extract a new shared source both point to), the user chose exact-match: *"take your option (2) — make your five rule descriptions character-for-character identical to what #141 ships... it costs nothing, and it converts a silent-divergence risk into a mechanical diff anyone can run. Option (1) is the FB-0010 fan-out hazard we keep getting bitten by; option (3) is new machinery, which the spike's 'build almost nothing' thesis rules out for a benefit this small."* Separately, on placement: *"Ben's actual use case is handing this to an agent in another repo — he copies it out. Portability matters; install-path does not."* Reinforced with independent evidence from a concurrent spike: `plugins/flow/docs/workflow.md` is an 85 KB file nothing `@`-imports, ~64% of a harness-weight audit's overstated total — *"Adding a new doc beside a file nothing loads would be adding to a graveyard."*

**Synthesized rule (1) — wording sync between sibling artifacts.** When two artifacts in-flight at the same time both derive structural/definitional content from one upstream source doc, don't have each artifact re-paraphrase the source independently ("close enough" wording drifts silently over time — the FB-0010 fan-out class). Also don't build a new shared-source mechanism for a benefit this small (new machinery the "build almost nothing" bar doesn't clear). Instead, whichever artifact ships second copies the first artifact's wording character-for-character. This converts an invisible-until-someone-notices divergence risk into a `diff`-able, mechanically-checkable relationship — cited so a future reader can literally verify it. **Confirmed at rebase (2026-09-03):** #141 merged as v1.37.0 while this branch was open; `template/base/core-docs/design-language.md` was re-fetched from `origin/main` and diffed against this brief's five rule descriptions — character-for-character identical, no drift.

**Synthesized rule (2) — placement for one-time/personal-use portable prompts.** Not everything useful belongs in the shipped plugin surface. When an artifact's realistic audience is "the repo owner copies this out and pastes it into an agent session" rather than "every flow consumer gets this automatically," and when at least one real target repo isn't even a flow consumer, prefer `dev-docs/` (flow's own, not shipped — but still copyable by hand) over `plugins/flow/docs/`. The generalizable signal, not just this instance: a shipped doc with nothing wiring it into any loaded context (no `@`-import, no skill reference, no trigger) is not more discoverable than a well-indexed dev-doc — it's a graveyard file that happens to ship. Shipping something doesn't make it load; loadedness is the property that matters, and it has to be verified, not assumed from location.

**Applies to:** any future PR adding a portable prompt/brief/reference doc where (a) a sibling artifact already derives from the same research doc, or (b) the realistic audience is narrower than "every flow consumer." Also feeds the open `docs/workflow.md`-graveyard finding into whatever PR fixes that specific file — this entry is not that fix, just the corroborating evidence for the placement call here.
