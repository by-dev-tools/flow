# Feedback Log

User feedback synthesized into actionable guidance. When the user gives feedback -- corrections, preferences, reactions, direction changes -- the relevant insight is captured here so it shapes all future work.

This is not a transcript. Each entry distills feedback into a rule or preference that applies going forward.

## One file per entry

**Every entry is its own file: `FB-XXXX-<slug>.md`.** There is no rollup and no index file, deliberately — either would recreate the merge conflict this structure exists to remove (every new entry would append a line to it). `ls dev-docs/feedback/` **is** the index, generated by the filesystem at zero conflict cost.

Read the whole corpus with `cat dev-docs/feedback/FB-*.md`. Reverse-chronological order is `ls -r`.

### Claiming an FB number

There is no reservations file any more (`dev-docs/reserved-feedback-numbers.md` was deleted when this directory was created). **Claiming a number is pushing the file.** Create `FB-XXXX-<slug>.md` and push it as its own commit before you invest in cross-file `FB-XXXX` references — that is the same early-push race detection the old protocol asked for, with the entry itself as the artifact instead of a line in a second file.

If two branches claim the same number, git reports a **both-added conflict on the filename**. That cannot be auto-merged and cannot be forgotten, which is the improvement: the old registry was a free-form log that git merged happily, and it recorded six separate renumbering incidents in its own audit trail.

## How to Write an Entry

```
### FB-XXXX: [Short summary of the feedback]
**Date:** YYYY-MM-DD
**Source:** user correction | user preference | user direction | review feedback

**What was said:** Brief, factual summary of the feedback.

**Synthesized rule:** The actionable takeaway -- what to do differently going forward.

**Applies to:** [areas this affects: ux, code, architecture, workflow, etc.]
```

The `### FB-XXXX` heading stays inside the file. It is what the entry census and the `resolve-doc-slot` reader key on, and it keeps a fragment readable when `cat`-ed together with its neighbours.

### Numbering
Increment from the last entry. Use `FB-0001`, `FB-0002`, etc. `ls dev-docs/feedback/ | tail -1` gives the current high-water mark.

### Source types
- **user correction** -- user fixed something you did wrong
- **user preference** -- user expressed a stylistic or process preference
- **user direction** -- user set strategic direction or priorities
- **review feedback** -- issues found during code/design review

## Known duplicate — scheduled, not lost

The `-a` file is a bare heading whose body was silently dropped by a clean auto-merge (PR #80 wrote it; #83/#84/#85 each touched the region); `-b` holds the real entry. Nothing was repaired at migration time — deleting from the durable record is a human judgment, and this is the reversible option. Resolve it whenever someone has the context; merging the two is a thirty-second job.
